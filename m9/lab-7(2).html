1. Pregătire: Java, sintaxă și mod de lucru

Programele Java din acest laborator au aceeași formă ca cele din C++: o clasă cu atribute private și operații publice, plus un program care o folosește. Diferențele de sintaxă sunt puține, dar modul de lucru este altul: fișierele sunt legate de numele claselor, iar compilarea și rularea se fac cu două comenzi distincte.

1.1 Clasă, obiect, instanță

Ideea de la care pornește orice program orientat pe obiecte este aceeași în C++ și în Java: o clasă este un șablon, iar un obiect este o realizare concretă a lui. Tutorialul Oracle spune că o clasă este planul după care se creează obiectele individuale, iar un obiect creat dintr-o clasă se numește instanță a ei. Clasa Fractie descrie ce are orice fracție, numarator și numitor, și ce poate face, seteaza și afiseaza; fiecare fracție concretă este o instanță.

Programul de mai jos creează două instanțe ale aceleiași clase și le dă valori diferite. Fiecare instanță are propriile ei atribute, deci schimbarea uneia nu o afectează pe cealaltă. Clasa nu conține main, pentru că ea nu este un program complet, ci numai planul fracțiilor; crearea și folosirea obiectelor se face în altă clasă, aici Main.

Java · Fractie.java
public class Fractie {
    private int numarator;
    private int numitor;

    public boolean seteaza(int a, int b) {
        if (b == 0) {
            return false;
        }
        numarator = a;
        numitor = b;
        return true;
    }

    public void afiseaza() {
        System.out.println(numarator + "/" + numitor);
    }
}
Java · Main.java
public class Main {
    public static void main(String[] args) {
        Fractie a = new Fractie();
        Fractie b = new Fractie();
        a.seteaza(1, 2);
        b.seteaza(3, 4);
        a.afiseaza();
        b.afiseaza();
    }
}

În Java, codul programelor din laborator se scrie în clase, iar chiar și main este o operație a unei clase. Java 21 are o variantă de probă (preview), dezactivată implicit, care permite subprograme în afara claselor; nu o folosim.

O clasă este șablonul: spune ce atribute și operații au obiectele ei. Un obiect, sau o instanță, este creat dintr-o clasă și are propriile valori ale atributelor. Poți crea oricâte instanțe ale unei clase, iar fiecare este creată de un constructor.

1.2 Un fișier pentru fiecare clasă publică

În C++ poți pune oricâte clase într-un fișier. În Java, o clasă declarată public trebuie să fie în fișierul cu exact același nume plus extensia .java. Clasa Fractie se află deci în Fractie.java, iar programul care o folosește, cu metoda main, într-o a doua clasă, Main, în Main.java.

    private int numitor;

        numarator = a;
        numitor = b;
        return true;

        System.out.println(numarator + "/" + numitor);

1.5 Variabilele de tip clasă sunt referințe

Cea mai importantă diferență de comportament: în C++, Fractie a; este chiar obiectul. În Java, o variabilă de tip clasă păstrează numai o referință la un obiect, iar obiectul se creează separat, cu new. Programul de la 1.2 arată consecința: b = a nu face o a doua fracție, ci a doua referință către aceeași fracție, deci schimbarea făcută prin b se vede și prin a, iar ambele linii afișează 3/4.

💡
Regulă: referințe în Java

O variabilă de tip clasă din Java indică un obiect, nu îl conține. Atribuirea b = a copiază referința, nu obiectul, iar obiectul poate fi schimbat prin oricare dintre cele două variabile. Un obiect nou apare numai când folosești new. Vei reîntâlni această regulă la secțiunea 3.3.

1.6 Mecanisme specifice Java pentru obiecte

Câteva mecanisme ale limbajului Java, pe care C++ nu le are sau le are altfel, apar în programele din laborator. Le vezi aici pe scurt, ca să nu te surprindă mai târziu.

1.6.1 null și NullPointerException

Pentru că o variabilă de tip clasă este o referință, ea poate să nu indice niciun obiect. Valoarea ei este atunci null. Apelul unei operații prin ea nu are ce obiect să folosească, iar programul se oprește la rulare cu NullPointerException; în C++, variabila Fractie f; este mereu un obiect, deci situația nu apare.

Java · Main.java
public class Main {
    public static void main(String[] args) {
        Fractie f = null;
        f.afiseaza();
    }
}
Se afișează
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "Fractie.afiseaza()" because "f" is null
	at Main.main(Main.java:4)

Mesajul spune ce operație s-a încercat, afiseaza(), ce variabilă era null și linia din program. Aceeași eroare apare în secțiunea 3.1.3, la tabloul cu elemente neinițializate.

1.6.2 Operatorul == compară referințele

La obiecte, == verifică dacă două variabile indică același obiect, nu dacă obiectele au aceleași valori. În programul de mai jos, a și b au amândouă valorile 1/2, dar sunt două obiecte distincte, iar c este o a doua referință către a.

Java · Main.java
public class Main {
    public static void main(String[] args) {
        Fractie a = new Fractie();
        a.seteaza(1, 2);
        Fractie b = new Fractie();
        b.seteaza(1, 2);
        Fractie c = a;
        System.out.println(a == b);
        System.out.println(a == c);
    }
}

Prima comparație dă false, a doua true. Pentru a compara valorile a două fracții scrii o operație proprie, nu folosești ==.

1.6.3 Obiectele transmise metodelor

În Java, parametrii se transmit prin valoare, iar pentru un obiect valoarea copiată este referința. Documentația Oracle spune că, după întoarcerea din metodă, referința transmisă indică în continuare același obiect ca înainte. În program, metoda schimba modifică obiectul indicat, iar metoda inlocuieste atribuie parametrului alt obiect.

Java · Main.java
public class Main {
    static void schimba(Fractie f) {
        f.seteaza(9, 9);
    }

    static void inlocuieste(Fractie f) {
        f = new Fractie();
        f.seteaza(5, 6);
    }

    public static void main(String[] args) {
        Fractie a = new Fractie();
        a.seteaza(1, 2);
        schimba(a);
        a.afiseaza();
        a.seteaza(1, 2);
        inlocuieste(a);
        a.afiseaza();
    }
}
Se afișează
9/9
1/2

Modificarea făcută de schimba se vede după apel, 9/9, pentru că metoda a lucrat pe același obiect. Atribuirea din inlocuieste schimbă doar parametrul, o copie a referinței, deci variabila a din main arată în continuare 1/2. Consecința pentru laborator: o transmitere către o metodă nu creează niciun obiect nou, deci în Java nu apare situația din secțiunea 3.3.2, în care transmiterea prin valoare apelează constructorul de copiere.

1.6.4 Obiectele nu se distrug manual

În Java creezi obiecte cu new și nu le distrugi. Mediul de execuție le elimină singur, prin colectorul de gunoi (garbage collector), atunci când constată că nu mai sunt folosite. Un obiect poate fi eliminat când nu mai există nicio referință către el, iar o referință dispare, de pildă, când variabila care o ține iese din domeniul ei. De aceea în programele Java din laborator nu scrii nicio operație de eliberare a obiectelor.

2.1 Problema: un obiect nou nu are valori

2.2 Ce este un constructor

Un constructor se scrie ca o operație care are exact numele clasei și nu are tip returnat, nici măcar void. Programul de mai jos pune în constructor și o afișare, doar ca să vezi când este apelat.

C++ · implicit.cpp
#include <iostream>
using namespace std;

class Fractie {
private:
    int numarator;
    int numitor;
public:
    Fractie() {
        cout << "constructor" << endl;
        numarator = 0;
        numitor = 1;
    }
    void afiseaza() {
        cout << numarator << "/" << numitor << endl;
    }
};

int main() {
    cout << "inainte" << endl;
    Fractie f;
    cout << "dupa" << endl;
    f.afiseaza();
    return 0;
}

Constructorul nu este apelat nicăieri în main. El rulează singur la linia Fractie f;, adică între inainte și dupa, și lasă obiectul cu valorile 0/1, o fracție validă. Afișarea din constructor este numai pentru demonstrație; un constructor obișnuit nu afișează nimic.

💡
Regulă: constructorul

Un constructor este o operație a clasei care are numele clasei, nu are tip returnat și este apelată automat la crearea unui obiect. Rolul lui este să dea atributelor valorile de început. Se scrie în secțiunea public:, ca să poată fi apelat din programele care creează obiecte.

În Java constructorul arată la fel: numele clasei, fără tip returnat. Obiectul se creează cu new, iar constructorul rulează în momentul acela.

3. Tipuri de constructori

Cele patru tipuri de constructori din tabelul de la 2.3 au fiecare câte o subsecțiune, în ordinea din tabel. Fiecare subsecțiune are aceeași formă: programul în C++, apoi același model în Java, apoi regula pe care o reții.

3.1 Constructorul implicit

3.1.1 Constructorul implicit scris de tine

Constructorul implicit nu primește parametri și dă obiectului o stare de început, aleasă de tine. Cursul de POO cere ca această stare să fie una standard, convențională sau neutră, dar validă din punctul de vedere al modelului. Pentru o fracție, o astfel de stare este 0/1, cea din programul de la 2.2.

Se apelează când obiectul se creează fără argumente: Fractie f; în C++, respectiv new Fractie() în Java. Parantezele goale după numele variabilei din C++ nu sunt corecte; vezi secțiunea 4.2.

3.1.2 Constructorul implicit generat de compilator

Clasa din secțiunea 2.1 nu avea constructor, și totuși Fractie f; a funcționat. Motivul este că, dacă o clasă nu declară niciun constructor, compilatorul C++ generează unul fără parametri, public, care are același efect ca un constructor cu corpul gol. Un constructor cu corpul gol nu dă nicio valoare atributelor int, de aceea ai văzut valori nespecificate.

Și Java generează un constructor fără parametri pentru o clasă care nu are niciunul, dar are o garanție în plus: atributele unui obiect nou primesc valori implicite, 0 pentru numere, false pentru boolean, null pentru obiecte. Tutorialul Oracle spune însă că a te baza pe aceste valori este considerat un stil slab de programare, iar exemplul arată de ce.

Java · Fractie.java
public class Fractie {
    private int numarator;
    private int numitor;

    public void afiseaza() {
        System.out.println(numarator + "/" + numitor);
    }
}
Java · Main.java
public class Main {
    public static void main(String[] args) {
        Fractie f = new Fractie();
        f.afiseaza();
    }
}
Se afișează
0/0

Valoarea 0/0 este garantată în Java, spre deosebire de C++, dar tot nu este o fracție validă. Garanția limbajului nu ține locul unui constructor care alege valori potrivite modelului.

💡
Regulă: constructorul implicit

Un constructor implicit este un constructor care poate fi apelat fără argumente. Dacă o clasă nu declară niciun constructor, compilatorul oferă unul care nu validează nimic. Dacă ai nevoie de o stare de început validă, scrii tu constructorul implicit.

3.2.4 Constructorul garantează o stare validă

Din secțiunea 3.2.1 programul acceptă Fractie f(3, 0); și creează o fracție cu numitorul 0, exact ce voiam să evităm în Laboratorul 6. Ca să lămurim ce înseamnă „stare validă”, folosim un termen din cursul de POO: invarianta clasei este regula, sau ansamblul de reguli, care trebuie să fie adevărată pe toată durata vieții unui obiect.

Fiecare clasă are propriile ei reguli. Pentru Fractie, numitorul nu poate fi 0; pentru clasa Cont din secțiunea 3.2.5, soldul nu poate fi negativ; pentru un cerc, raza nu poate fi negativă. Primul constructor din secțiunea 3.2.1 face doar prima.

Un constructor nu poate întoarce bool, deci nu poate spune programului că valorile au fost refuzate.     int numitor;

    }

3.4 Constructorul de mutare

3.4.1 Ideea

Constructorul de mutare creează tot un obiect nou pornind de la unul existent, dar nu îl copiază, ci preia starea lui. Obiectul sursă rămâne valid, într-o stare minimală. Cursul de POO îl descrie ca transfer al controlului asupra resurselor, iar diferența față de copiere contează când copierea ar fi costisitoare, de pildă la un tablou mare.

În C++, un constructor de mutare are parametrul Clasa&&. Obiectul care trebuie mutat se marchează cu move, din <utility>; move singur nu mută nimic, ci doar permite apelarea constructorului de mutare.

3.4.2 Exemplu în C++

Clasa Fractie are doar numere, deci o mutare nu câștigă nimic față de o copiere; programul o folosește ca să vezi sintaxa și ce se întâmplă cu sursa. Constructorul preia valorile, apoi lasă sursa într-o stare validă aleasă de noi, 0/1, ca să nu încalce invarianta.

C++ · mutare.cpp
#include <iostream>
#include <utility>
using namespace std;

class Fractie {
private:
    int numarator;
    int numitor;
public:
    Fractie(int a, int b) {
        numarator = a;
        numitor = b;
    }
    Fractie(Fractie&& f) {
        cout << "mutare" << endl;
        numarator = f.numarator;
        numitor = f.numitor;
        f.numarator = 0;
        f.numitor = 1;
    }
    void afiseaza() {
        cout << numarator << "/" << numitor << endl;
    }
};

int main() {
    Fractie a(3, 4);
    Fractie b = move(a);
    a.afiseaza();
    b.afiseaza();
    return 0;
}

Constructorul de mutare a rulat la move(a). Obiectul a există în continuare și poate fi afișat, dar are acum valorile pe care le-a lăsat constructorul, 0/1, iar b are valorile lui a de dinainte, 3/4. La obiectele din biblioteca standard, starea unui obiect mutat este „validă, dar nespecificată”; pentru clasele tale tu hotărăști starea sursei și o documentezi.

💡
Regulă: constructorul de mutare

Un constructor de mutare are forma Clasa(Clasa&& alt) și se apelează la Clasa b = move(a);. El preia starea lui a și trebuie să lase obiectul a într-o stare validă. După mutare, a nu se mai folosește pentru valoarea lui de dinainte.

3.4.3 În Java

Java nu are constructor de mutare. Cuprinsul specificației limbajului, la capitolul despre declararea constructorilor, nu listează un astfel de constructor, iar secțiunea 1.5 arată de ce nu este nevoie de el: variabilele păstrează referințe, deci un obiect nu se copiază și nu se mută la atribuire, ci este pur și simplu indicat de mai multe variabile.

#include <iostream>
using namespace std;

class Fractie {
private:
    int numarator;
    int numitor;
    int cmmdc(int a, int b) {
        while (b != 0) {
            int r = a % b;
            a = b;
            b = r;
        }
        return a;
    }
public:
    Fractie() {
        numarator = 0;
        numitor = 1;
    }
    Fractie(int n, int d) {
        if (d == 0 || n == 0) {
            numarator = 0;
            numitor = 1;
        } else {
            if (d < 0) {
                n = -n;
                d = -d;
            }
            int modul = n;
            if (n < 0) {
                modul = -n;
            }
            int g = cmmdc(modul, d);
            numarator = n / g;
            numitor = d / g;
        }
    }
    void afiseaza() {
        cout << numarator << "/" << numitor << endl;
    }
};

int main() {
    int n, d;
    cin >> n >> d;
    Fractie a(n, d);
    cin >> n >> d;
    Fractie b(n, d);
    Fractie c;
    a.afiseaza();
    b.afiseaza();
    c.afiseaza();
    return 0;
}

Întrebări de autoevaluare

1. Ce este un constructor și când se execută?

Este o operație specială a clasei, cu același nume ca ea și fără tip returnat, care se execută automat în momentul în care un obiect este creat. Rolul ei este să aducă obiectul într-o stare de început validă.

2. Care sunt cele patru tipuri de constructori și prin ce se deosebesc?

Constructorul implicit poate fi apelat fără argumente; cel cu parametri primește valorile inițiale; cel de copiere creează un obiect din alt obiect de același tip și primește sursa printr-o referință; cel de mutare creează un obiect preluând valorile unei surse care nu mai este necesară și o lasă într-o stare validă. Compilatorul alege automat constructorul potrivit, după argumentele din declarație.

3. Ce se întâmplă cu constructorul implicit generat de compilator dacă scrii un constructor cu parametri?

Dispare. Compilatorul generează constructorul implicit numai când clasa nu declară niciun constructor. Dacă este nevoie și de varianta fără argumente, de exemplu pentru Dreptunghi v[3];, trebuie scrisă.

4. De ce are nevoie de un constructor implicit linia Dreptunghi v[3];?

Fiecare dintre cele trei elemente este un obiect și trebuie creat, iar pentru elementele unui vector nu se dau argumente. Dacă nu există un constructor apelabil fără argumente, programul nu compilează.

5. Ce este invarianta unei clase și cine o apără?

Este o condiție adevărată pentru orice obiect valid, de exemplu „numitorul este diferit de 0”. Constructorul o face adevărată la creare, iar operațiile care modifică atributele o păstrează.

6. Cum reutilizează un constructor regula de validare a unui setter?

Apelează setterul și, dacă acesta refuză valorile, pune o stare de rezervă validă, de exemplu 0/1. Astfel regula este scrisă într-un singur loc.

7. Când se apelează constructorul de copiere?

La crearea unui obiect din altul, T b = a; sau T c(a);, și când un obiect este transmis unui subprogram prin valoare. La transmiterea prin referință nu se apelează.

8. De ce nu poate avea constructorul de copiere un parametru prin valoare?

Un parametru prin valoare ar trebui creat prin copiere, adică printr-un apel al aceluiași constructor, care ar cere altă copie și așa mai departe. Compilatorul refuză forma și sugerează const T&.

9. Ce deosebește b = a în C++ de același rând în Java?

În C++ este o copie a obiectului (sau, la declarare, apelul constructorului de copiere). În Java variabilele de tip clasă sunt referințe, deci b = a face din b alt nume pentru același obiect; o copie se obține numai cu new și un constructor.

10. Ce rol are this(...) într-un constructor Java și ce impune final pentru un atribut?

this(...) apelează un alt constructor al aceleiași clase, ca regula de inițializare să fie scrisă o singură dată. Un atribut final trebuie atribuit în fiecare constructor și nu mai poate fi schimbat după aceea.
