Introducere

Modulul M9 folosește trei limbaje: C++ pentru programele pe care le scrii tu, iar Java și Python pentru comparație. Înainte de orice noțiune nouă, trebuie să fie clar un lucru foarte practic: cum ajunge un fișier de text să fie un program care rulează, și ce faci când nu rulează. Acest laborator răspunde exact la aceste două întrebări, pentru fiecare dintre cele trei limbaje.

Programul folosit peste tot este cel mai mic posibil: afișează un mesaj. El este suficient pentru a vedea toți pașii: fișierul sursă, traducerea (acolo unde există), rularea și, mai ales, mesajele de eroare. Ele vor reveni în fiecare laborator următor, deci merită să înveți de acum să le citești.

La finalul acestui laborator vei putea să:

  1. Compilezi și rulezi un program minim în C++, Java și Python
  2. Numești ce produce fiecare pas (executabil, bytecode) și ce execută rezultatul
  3. Explici de ce o eroare de sintaxă apare în momente diferite în cele trei limbaje
  4. Citești un mesaj de eroare: fișierul, linia și ce lipsește sau ce nu este cunoscut
  5. Distingi erorile de compilare, de execuție și de logică, după momentul în care apar
  6. Corectezi trei erori frecvente: caracter lipsă, nume necunoscut, nume de fișier nepotrivit în Java

1. Mediul de lucru: de la fișierul sursă la program

Un fișier sursă este un fișier text care conține codul scris de programator. Calculatorul nu îl poate executa direct, iar drumul de la sursă la un program care rulează diferă de la un limbaj la altul. În C++, compilatorul (de exemplu g++) traduce fișierul sursă într-un fișier executabil, pe care sistemul de operare îl poate rula. În Java, compilatorul javac produce un fișier .class care conține bytecode, iar comanda java pornește mașina virtuală Java (JVM), care execută acel bytecode. În Python, programul se dă direct interpretorului (python3), care îl rulează fără ca tu să creezi un executabil.

Programul minim în cele trei limbaje

    cout << "Salut, POO!" << endl;
    return 0;
}

    }

Se afișează – identic în cele trei limbaje

Toate cele trei programe afișează același mesaj, dar structura lor diferă. În C++, execuția pornește din funcția main, iar cout vine din biblioteca inclusă cu #include <iostream>. În Java, orice instrucțiune trebuie să se afle într-o clasă, iar execuția pornește din metoda main a clasei indicate la comanda java. În Python nu există o structură obligatorie: instrucțiunile fișierului se execută una după alta, de sus în jos.

💡
Clasic: „C++ e compilat, Java e interpretat, Python e interpretat”

Formularea este prea simplă. Java este mai întâi compilat (în bytecode) și abia apoi bytecode-ul este executat de JVM. Documentația Python spune că Python este un limbaj interpretat, dar adaugă că distincția „poate fi neclară din cauza compilatorului de bytecode”: în implementarea CPython, codul sursă este compilat intern în bytecode, executat apoi de o mașină virtuală. Corect este să descrii ce pași apar și ce produce fiecare, nu să aplici o etichetă unică limbajului. Mai mult, un limbaj nu este în sine „compilat” sau „interpretat”: modul de execuție ține de implementare. Aici vorbim despre g++, javac + JVM și CPython.

2. Tipuri de erori

Un program poate fi greșit în feluri foarte diferite. Pentru a-l repara, primul lucru de aflat este când se vede greșeala și cine o observă: compilatorul, programul care rulează sau tu. După aceste două întrebări, erorile se împart în trei categorii, pe care le vei recunoaște în toate laboratoarele următoare.

Cele trei momente în care poate apărea o eroare
1. Compilareverificarea textului; dacă nu respectă regulile, nu se produce niciun program
→
2. Execuțieprogramul pornește, dar întâlnește o operație imposibilă și se oprește
→
3. Rezultatprogramul se termină normal, dar rezultatul este greșit; îl descoperi tu
Memorează: compilare → mesaj de la compilator; execuție → mesaj de la program, în timp ce rulează; logică → niciun mesaj.

2.1. Erori de compilare (de sintaxă)

Un limbaj de programare are reguli: ce cuvinte există, cum se scriu instrucțiunile, ce nume trebuie declarate înainte de folosire. Dacă textul le încalcă, compilatorul nu poate traduce programul și te anunță înainte ca ceva să ruleze. Este categoria cea mai ușoară: mesajul îți spune fișierul, linia și ce nu înțelege. Mai jos, programul folosește o variabilă care nu a fost declarată; mesajul este cel real, produs de g++.

C++ · nume.cpp
#include <iostream>
using namespace std;

int main() {
    int a = 8;
    cout << a + b << endl;
    return 0;
}
g++ – mesajul real
nume.cpp:6:17: error: ‘b’ was not declared in this scope
💡
Definiție: eroare de compilare

O eroare de compilare (eroare de sintaxă, în sens larg) este o încălcare a regulilor limbajului, descoperită înainte de execuție. Programul nu se poate crea (în C++ și Java) sau nu începe să ruleze (în Python, unde interpretorul verifică textul înainte să execute prima instrucțiune). Exemple: lipsește ;, un nume nu este declarat, o paranteză nu este închisă.

2.2. Erori la execuție

Uneori textul este corect: compilatorul îl acceptă și programul pornește. Dar în timpul rulării apare o operație care nu se poate face, de exemplu o împărțire la zero. Programul se oprește chiar în acel loc. Observă că ce a fost afișat înainte de oprire rămâne pe ecran, iar ce urma după nu se mai execută. Cele trei programe de mai jos fac același lucru; rezultatele sunt cele reale.

C++ · impartire.cpp
#include <iostream>
using namespace std;

int main() {
    int a = 5;
    int b = 0;
    cout << "Inainte de impartire" << endl;
    cout << a / b << endl;
    cout << "Dupa impartire" << endl;
    return 0;
}

În niciunul dintre cazuri nu s-a afișat „Dupa impartire”. Textul exact al mesajului din C++ depinde de sistemul de operare și de shell.

💡
Definiție: eroare la execuție

O eroare la execuție este o situație în care un program corect din punct de vedere al sintaxei întâlnește, în timp ce rulează, o operație imposibilă (împărțire la zero, deschiderea unui fișier care nu există, un indice în afara unui vector în Java sau Python). Programul se oprește în acel punct. În Java și Python astfel de situații se numesc excepții.

2.3. Erori de logică

Cea mai înșelătoare categorie este cea în care nimeni nu te anunță. Programul compilează, rulează până la capăt, nu afișează nicio eroare, dar răspunsul nu este cel cerut. Exemplu: media a două note trebuie să fie (a + b) / 2. Dacă uiți parantezele, regula priorității operațiilor împarte doar pe b, iar rezultatul este altul.

C++ · media.cpp
#include <iostream>
using namespace std;

int main() {
    int a = 8;
    int b = 4;
    cout << a + b / 2 << endl;
    return 0;
}
Se afișează
10

Media lui 8 și 4 este 6, dar programul afișează 10, fără niciun mesaj. Eroarea se găsește numai prin verificare: calculezi pe hârtie pentru valori mici și compari cu ce afișează programul.

💡
Definiție: eroare de logică

O eroare de logică este o greșeală în algoritm sau în felul în care este scris, care nu încalcă regulile limbajului. Programul compilează și rulează complet, dar produce un rezultat diferit de cel cerut. Se descoperă prin testare (valori la care știi răspunsul) și prin urmărirea programului pe hârtie.

2.4. Avertismente

Între eroare și program corect există un nivel intermediar: avertismentul. Compilatorul traduce programul, dar te anunță că a găsit ceva suspect. Cu opțiunea -Wall, g++ avertizează, de exemplu, asupra unei variabile declarate și nefolosite.

C++ · avert.cpp
#include <iostream>
using namespace std;

int main() {
    int n = 5;
    cout << "Salut" << endl;
    return 0;
}
Comanda
g++ -std=c++17 -Wall avert.cpp -o avert
g++ – avertismentul real
avert.cpp:5:9: warning: unused variable ‘n’ [-Wunused-variable]

Programul s-a compilat și se poate rula, dar avertismentul merită citit: variabila n a fost declarată degeaba, iar uneori un avertisment arată o greșeală de logică.

2.5. Când nu te anunță nimeni

În C++ există și greșeli pe care nici compilatorul, nici programul nu le semnalează, de exemplu citirea unui element în afara vectorului: la int v[3], instrucțiunea v[5] este greșită, dar programul poate continua să ruleze și să afișeze o valoare oarecare. Standardul limbajului spune că într-un astfel de caz nu există nicio cerință asupra comportamentului programului; el se numește comportament nedefinit, iar compilatorul nu este obligat să îl semnaleze. Din acest motiv, la vectori respectăm mereu regula „indici valizi: 0 … n − 1”.

3. Erori frecvente

Eroarea 1 – Ai uitat un caracter obligatoriu (; sau o paranteză)

Cu o instrucțiune neterminată, programul nici nu pornește. Mesajele cele mai utile sunt primele: ele spun fișierul, linia și ce lipsește. Cele de mai jos sunt cele reale produse de g++ 13.3, javac 21 și Python 3.13 pentru programul „Salut, POO!” din care s-a șters ; (în C++ și Java), respectiv paranteza de închidere (în Python).

Fișierul E5.java conține clasa publică Altceva. Compilarea cu javac eșuează:

Regula este impusă de javac, nu de limbajul Java în sine: specificația limbajului (JLS 7.6) spune că sistemul gazdă poate impune ca un tip public să se afle într-un fișier cu același nume. În practică, cu javac, clasa publică Hello se află în Hello.java.

4. Cum tratezi o eroare

Oricine programează întâlnește erori, și începătorii, și cei cu experiență. Diferența nu este că unii nu greșesc, ci că au o metodă: nu schimbă la întâmplare bucăți din program, ci îl cercetează pas cu pas. Procesul de căutare și reparare a erorilor se numește depanare (în engleză, debugging). Metoda de mai jos este o prezentare didactică a autorului materialului, adunată din practica obișnuită; ea nu provine dintr-o sursă anume.

Șase pași pentru orice eroare
1. Citeștemesajul, dacă există: fișier, linie, descriere
→
2. Localizeazăunde apare: care linie, care valoare
→
3. Ghicește cauzaformulează o singură ipoteză
→
4. Schimbă un lucrudoar unul, ca să știi ce a ajutat
→
5. Rulează din nouși citește iar mesajul
→
6. Verificăcu valori la care știi răspunsul
Memorează: citești → localizezi → ipoteză → o schimbare → rulezi → verifici.
💡
Trei reguli care economisesc timp

1. Prima eroare întâi. Una singură poate produce mai multe mesaje; după ce o repari, recompilează înainte să treci mai departe. 2. O schimbare, o rulare. Dacă schimbi cinci lucruri deodată, nu mai știi care a rezolvat problema (sau a stricat altceva). 3. Nu rescrie tot. Dacă programul avea o singură greșeală, rescrierea lui produce, de obicei, altele noi.

4.1. Eroare de compilare: o cauză, mai multe mesaje

Programului de mai jos îi lipsește prima linie, #include <iostream>. Compilatorul nu cunoaște nici cout, nici endl și raportează două mesaje pentru o singură cauză. Observă și linia note: uneori g++ sugerează chiar remedierea.

C++ · fara.cpp
using namespace std;

int main() {
    int a = 8;
    cout << a << endl;
    cout << a + 1 << endl;
    return 0;
}
g++ – mesajele reale (selecție)
fara.cpp:5:5: error: ‘cout’ was not declared in this scope
fara.cpp:1:1: note: ‘std::cout’ is defined in header ‘<iostream>’; did you forget to ‘#include <iostream>’?
fara.cpp:5:18: error: ‘endl’ was not declared in this scope
fara.cpp:1:1: note: ‘std::endl’ is defined in header ‘<ostream>’; did you forget to ‘#include <ostream>’?

Aplicăm pașii: citim primul mesaj (cout nu este cunoscut) și nota de sub el, localizăm locul, ipoteza este că lipsește includerea, schimbăm un singur lucru (adăugăm linia) și rulăm din nou. Ambele mesaje dispar, pentru că aveau aceeași cauză.

C++ · fara.cpp (după corectare)
#include <iostream>
using namespace std;

int main() {
    int a = 8;
    cout << a << endl;
    cout << a + 1 << endl;
    return 0;
}
Se afișează
8
9

4.2. Eroare de logică: afișări de control

Când nu există niciun mesaj, programul trebuie făcut să „vorbească”. O afișare de control este o instrucțiune pusă temporar în program, care arată valoarea unei variabile sau a unei expresii într-un anumit loc. Revenim la media lui 8 și 4, care ieșea 10. Afișăm pe rând părțile expresiei și o comparăm cu rezultatul scris pe hârtie.

C++ · control.cpp
#include <iostream>
using namespace std;

int main() {
    int a = 8;
    int b = 4;
    cout << "b / 2 = " << b / 2 << endl;
    cout << "a + b / 2 = " << a + b / 2 << endl;
    cout << "(a + b) / 2 = " << (a + b) / 2 << endl;
    return 0;
}
Se afișează
b / 2 = 2
a + b / 2 = 10
(a + b) / 2 = 6

Pe hârtie, media lui 8 și 4 este 6. Afișarea arată că b / 2 se calculează primul (rezultat 2), apoi se adună 8: ipoteza „împărțirea se face înaintea adunării” este confirmată, iar a treia linie arată forma corectă. După reparare, afișările de control se șterg.

4.3. Programul își tratează singur situația

Unele erori la execuție pot fi evitate dacă programul verifică înainte de a face operația riscantă. Împărțirea la zero din secțiunea 2.2 poate fi prevenită cu o condiție: dacă împărțitorul este 0, programul afișează un mesaj și nu mai încearcă împărțirea.

C++ · impartire_sigura.cpp
#include <iostream>
using namespace std;

int main() {
    int a = 5;
    int b = 0;
    if (b == 0) {
        cout << "Nu se poate imparti la zero" << endl;
    } else {
        cout << a / b << endl;
    }
    return 0;
}
Se afișează
Nu se poate imparti la zero
💡
De reținut

Să tratezi o eroare înseamnă două lucruri diferite: (1) o repari în program, când este o greșeală de-a ta (compilare, logică), și (2) previi situația cu o verificare, când ea poate apărea din datele de intrare (împărțitor zero, fișier lipsă).

Întrebări de autoevaluare

1. Ce produce fiecare pas la compilarea și rularea unui program în C++, Java și Python?

C++: g++ produce un executabil, care se rulează direct. Java: javac produce un fișier .class cu bytecode, executat de JVM prin java. Python: python3 rulează fișierul sursă; nu creezi tu un fișier intermediar. Erorile de sintaxă apar la compilare în C++ și Java, iar în Python, la pornire, înainte să se execute vreo instrucțiune.

  • Drumul de la sursă la program diferă: executabil în C++, bytecode + JVM în Java, interpretor în Python. Descrie pașii, nu pune etichete.
    • Fișier sursăFișier text cu codul scris de programatorExecutabilFișier produs de compilator (C++), pe care sistemul de operare îl poate rulaBytecodeCod intermediar produs de javac și executat de JVM
    2. De ce o eroare de sintaxă poate fi raportată pe o altă linie decât cea în care a apărut?

    Pentru că programul își dă seama de lipsă abia când întâlnește ceva ce nu se potrivește. În exemplul cu ; lipsă, g++ observă problema când ajunge la instrucțiunea următoare. Citește mesajul și verifică și linia dinainte.

    3. Ce înseamnă „cannot find symbol” (Java) sau „was not declared in this scope” (C++)?

    Că programul folosește un nume pe care compilatorul nu îl cunoaște: o variabilă nedeclarată, un nume scris greșit sau un text pus fără ghilimele. Corectura este să declari numele sau să-l scrii corect.

    4. Ce rol au opțiunile -Wall -Wextra?

    Cer lui g++ să avertizeze asupra construcțiilor suspecte, chiar dacă programul se poate compila. Avertizările nu opresc compilarea, dar merită citite.

    5. Care sunt cele trei categorii de erori și prin ce se deosebesc?

    Erori de compilare (încalcă regulile limbajului, se descoperă înainte de execuție), erori la execuție (programul pornește, apoi se oprește la o operație imposibilă) și erori de logică (programul rulează complet, dar rezultatul este greșit). Diferența este momentul și cel care o observă.

    6. De ce sunt erorile de logică cele mai greu de găsit?

    Pentru că nu există niciun mesaj: programul se termină normal. Le găsești testând cu valori la care știi răspunsul și urmărind programul pe hârtie.

    7. Ce este un avertisment și prin ce diferă de o eroare?

    Este un mesaj prin care compilatorul semnalează ceva suspect, dar produce totuși programul. O eroare de compilare oprește producerea programului.

    8. Care sunt pașii de căutare și reparare a unei erori?

    Citești mesajul (dacă există), localizezi locul, formulezi o ipoteză, schimbi un singur lucru, rulezi din nou și verifici cu valori cunoscute.

    9. Ce înseamnă „o schimbare, o rulare” și de ce contează?

    După fiecare modificare rulezi programul. Altfel nu poți ști care modificare a rezolvat eroarea sau a produs alta.

    10. Cum previi o eroare la execuție, în loc s-o repari?

    Verifici înainte de operația riscantă (de exemplu, dacă împărțitorul este 0) și tratezi cazul separat, cu un mesaj.
