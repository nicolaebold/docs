1. Reamintire: subprograme

Un subprogram (în C++ și Python îl numim funcție, în Java metodă) este o secvență de instrucțiuni cu un nume, care poate fi apelată de oricâte ori și, la nevoie, primește date și returnează un rezultat. Definiția conține tipul returnat (în C++ și Java), numele, lista de parametri și corpul; apelul scrie numele și, între paranteze, valorile (argumentele) cu care se execută. Tipul void arată că subprogramul nu returnează nicio valoare, iar instrucțiunea return încheie execuția și trimite rezultatul. Variabilele declarate în interiorul unui subprogram sunt locale: există numai cât timp se execută el. Chiar main este un subprogram, cel din care pornește execuția în C++ și Java.

Cele patru părți ale unui subprogram (funcție)
1int 2maxim(3int a, int b) {
    4if (a > b) { return a; }
    4return b;
}
  • 1Tipul returnat – felul rezultatului (int, bool, void = nimic)
  • 2Numele – spune ce face: maxim, nu f1
  • 3Parametrii – datele primite, fiecare cu tipul lui
  • 4Corpul – instrucțiunile executate la apel; return trimite rezultatul
Obligatorii: tip, nume, parametri (pot lipsi ca listă, dar parantezele rămân) și corp. Antetul = părțile 1 + 2 + 3.
Apelul unui subprogram
int m = 1maxim(2x, y + 1);
  • 1Numele apelat – trebuie să coincidă cu cel din antet
  • 2Argumentele – valorile transmise; se potrivesc, în ordine, cu parametrii
Parametru = variabila din antet; argument = valoarea din apel.

Programul de mai jos conține trei subprograme: maxim returnează cel mai mare dintre două numere, afiseazaNota afișează un mesaj și nu returnează nimic, iar incearcaSaSchimbi modifică parametrul primit. Ultimul arată un fapt important: pentru un număr întreg trimis ca argument, subprogramul lucrează pe propria lui valoare, iar variabila din care a fost luat argumentul nu se schimbă.

1.1. De ce avem subprograme: ce se repetă

Motivul principal pentru care există subprogramele este repetarea. Dacă ai nevoie de același calcul pentru date diferite (de trei ori, de zece ori, într-o buclă), nu îl scrii de fiecare dată din nou: îl scrii o singură dată, îi dai un nume și îl apelezi cu datele de fiecare dată. Mai jos, aceeași instrucțiune este scrisă de trei ori, cu alte valori; părțile colorate sunt singurele care se schimbă.

Fără subprogram: același text, alte date
if (2a > 2b) m1 = 2a; else m1 = 2b;
if (2c > 2d) m2 = 2c; else m2 = 2d;
if (2e > 2f) m3 = 2e; else m3 = 2f;
  • 2Datele – se schimbă la fiecare repetare; tot ce nu este colorat se repetă identic
Semnal: dacă ai copiat o bucată de program și ai schimbat doar câteva valori, bucata respectivă trebuie să devină subprogram.
Cu subprogram: calculul scris o dată, datele schimbate la apel
1int maxim(int x, int y) { if (x > y) return x; return y; }

m1 = 3maxim(2a, b);
m2 = 3maxim(2c, d);
m3 = 3maxim(2e, f);
  • 1Definiția – calculul se scrie o singură dată
  • 3Apelurile – același nume, de câte ori ai nevoie
  • 2Argumentele – datele care se schimbă; ele devin parametrii
Regula de aur: ce se repetă devine corpul subprogramului; ce se schimbă devine parametri.
💡
Ce câștigi

Scrii o dată: mai puțin text. Repari o dată: dacă ai o greșeală, o corectezi într-un singur loc, nu în trei. Citești mai ușor: maxim(a, b) spune ce se întâmplă, fără să citești instrucțiunea. Refolosești: același subprogram poate fi apelat într-o buclă sau chiar din alt subprogram.

1.2. Modularitatea: împărțim problema în bucăți

Repetarea nu este singurul motiv pentru subprograme. Când o problemă este mare, nu o rezolvi dintr-o dată: o desparți în subprobleme mai mici și rezolvi fiecare subproblemă separat. Fiecare subproblemă devine un subprogram; programul principal, main, doar citește datele și coordonează subprogramele. Acest fel de a scrie programe se numește modularitate. Observă că aici fiecare subprogram poate fi apelat o singură dată: scopul nu este să evităm copierea, ci să avem bucăți mici, clare, care se pot înțelege și testa pe rând.

Definiție: modularitate

Modularitatea este împărțirea unui program în părți (module) independente, fiecare cu o sarcină bine precizată. În programele pe care le scriem acum, modulele sunt subprogramele. Avantaje: problema mare devine mai ușor de rezolvat, fiecare bucată se testează separat, iar bucățile bune pot fi refolosite în alte programe. Idee preluată (în traducere liberă) din Programming Fundamentals – Modular Programming; formularea în română și exemplele sunt ale autorului materialului.

2. Cum scrii un subprogram: trei întrebări

Când ai de rezolvat o sarcină și vrei să o scrii ca subprogram, răspunde, în ordine, la trei întrebări. Ele aleg aproape tot ce trebuie scris în antet.

Cele trei întrebări → antetul
1bool 3estePrim(2int n)
  • 1Ce returnează? – o valoare cu două stări: bool
  • 2Ce primește? – un număr întreg: parametrul int n
  • 3Cum se numește? – un nume care spune ce face: estePrim
Ordinea întrebărilor: primește → returnează → nume; ordinea în antet: returnează, nume, primește.
  1. Ce primește? Datele de care are nevoie, fiecare cu un tip: devin parametrii.
  2. Ce returnează? Un rezultat de un anumit tip (int, bool, ...), sau nimic (void), dacă doar afișează sau face o acțiune.
  3. Cum se numește? Un nume care spune ce face: estePrim, maxim, nu f1.

Exemplu: „este numărul n prim?”. Primește un int, returnează o valoare cu două stări (bool), se numește estePrim.

C++ · prim.cpp
#include <iostream>
using namespace std;

bool estePrim(int n) {
    if (n < 2) {
        return false;
    }
    for (int d = 2; d * d <= n; d++) {
        if (n % d == 0) {
            return false;
        }
    }
    return true;
}

int main() {
    cout << estePrim(7) << " " << estePrim(8) << " " << estePrim(1) << endl;
    return 0;
}

3. Erori frecvente

Eroarea 1 – Lipsește return într-o funcție care trebuie să returneze

Funcția dublu calculează r, dar nu îl returnează. Compilatorul nu o refuză, ci doar avertizează, și numai dacă ai cerut avertizări (-Wall):

C++ · dublu.cpp
#include <iostream>
using namespace std;

int dublu(int x) {
    int r = x * 2;
}

int main() {
    cout << dublu(4);
    return 0;
}
g++ -Wall
dublu.cpp:5:9: warning: unused variable ‘r’ [-Wunused-variable]
dublu.cpp:6:1: warning: no return statement in function returning non-void [-Wreturn-type]

În C++, ieșirea dintr-o funcție care returnează valoare, fără return, este comportament nedefinit dacă folosești rezultatul: programul poate afișa orice. Tocmai de aceea merită să compilezi cu -Wall și să citești avertizările.

Eroarea 2 – Apelul înainte de definiție

În C++, un subprogram trebuie să fie cunoscut înainte de a fi apelat; aici, dublu este scris după main.

g++
ordine.cpp:5:13: error: ‘dublu’ was not declared in this scope; did you mean ‘double’?

În Python, def este o instrucțiune care se execută: dacă apelul vine înaintea ei, numele încă nu există.

python3
NameError: name 'dublu' is not defined

Eroarea 3 – Folosirea rezultatului unui subprogram void

Un subprogram void nu returnează nimic, deci nu poți păstra rezultatul într-o variabilă.

g++
voidv.cpp:9:21: error: void value not ignored as it ought to be

Căutarea într-un vector, ca subprogramMedie

Cerință

Scrie un subprogram care primește un vector de numere întregi, numărul lui de elemente și o valoare x și returnează indicele primei apariții a lui x, sau −1 dacă x nu apare. Apelează-l pentru două valori.

Reprezentare
  1. Lucrul și întrebarea: o colecție de numere și întrebarea „unde este x?”.

  • d) ca să evităm complet erorile

Întrebări de autoevaluare

1. Ce este un subprogram și ce înseamnă „variabilă locală”?

Un subprogram este o secvență de instrucțiuni cu nume, apelabilă de oricâte ori, care poate primi parametri și returna o valoare. O variabilă locală este declarată în interiorul lui și există numai cât timp se execută subprogramul.

  • Un subprogram are tip returnat (C++ și Java), nume, parametri și corp; variabilele lui sunt locale. Pentru argumente numerice, subprogramul lucrează pe o copie.
    • SubprogramSecvență de instrucțiuni cu nume, apelabilă, care poate primi parametri și returna o valoare
    2. Care este diferența dintre parametru și argument?

    Parametrul este variabila din antetul definiției (int a), iar argumentul este valoarea dată la apel (7). La apel, parametrul primește valoarea argumentului.

    3. De ce se folosesc subprograme?

    Pentru că o secvență de instrucțiuni scrisă o dată poate fi apelată de oricâte ori, programul se împarte în părți cu nume, iar fiecare parte se verifică separat. Aceste motive sunt formulări didactice ale autorului, nu citate din vreo sursă.

    4. Ce se întâmplă în C++ dacă o funcție care trebuie să returneze o valoare ajunge la final fără return?

    Compilatorul poate doar avertiza (cu -Wall), iar folosirea rezultatului este comportament nedefinit. Nu pot confirma asta dintr-o citare a standardului în acest material; regula este prezentată ca regulă cunoscută a limbajului și avertismentul a fost verificat cu g++ 13.3.

    5. De ce un subprogram nu schimbă un argument numeric din main?

    Pentru că parametrul este o copie a valorii argumentului. Concluzia a fost verificată pentru int; pentru vectori și obiecte regula diferă între limbaje.

    6. Ce legătură este între repetare și subprograme?

    Dacă același calcul se face de mai multe ori, cu date diferite, el se scrie o singură dată ca subprogram și se apelează cu datele potrivite. Ce se repetă devine corpul, ce se schimbă devine parametri.

    7. De ce este mai simplu să repari un calcul scris ca subprogram?

    Pentru că există într-un singur loc: îl corectezi o dată, iar toate apelurile îl folosesc. Dacă ar fi copiat în mai multe locuri, ar trebui corectat în fiecare.

    8. Ce este modularitatea?

    Împărțirea unui program în părți independente, fiecare cu o sarcină precisă; la noi, părțile sunt subprogramele. O problemă mare se desparte în subprobleme, iar main le coordonează.

    9. Prin ce diferă modularitatea de repetare?

    Repetarea cere un subprogram pentru că același calcul apare de mai multe ori; modularitatea cere subprograme pentru că problema este mare, chiar dacă fiecare bucată apare o singură dată.
