Introducere

Un program lucrează cu date, iar felul în care alegi să reprezinți datele hotărăște cât de simplu sau de greu devine restul programului. Modulul M9 construiește, pas cu pas, instrumente pentru a grupa și a proteja datele: mai întâi o structură simplă (struct), apoi clasa, apoi cele patru principii ale programării orientate pe obiecte. Toate pornesc de la câteva idei pe care le-ai întâlnit deja, dar de obicei separat: ce este un tip de date, ce este o variabilă, cum se construiesc vectorii și matricele, cum alegi o formă pentru o informație din realitate.

Laboratorul le așază într-o hartă, ca să vezi ce relație este între ele. Are două scopuri. Primul este teoretic: tipul de date, variabila, vectorul, matricea și textul sunt prezentate ca părți ale aceleiași scheme, nu ca vocabular izolat. Al doilea este de modelare: pornești de la un lucru din realitate și ajungi, prin pași clari, la o reprezentare în program.

1. Harta datelor: tip, valoare, variabilă, structură

Cuvintele tip, valoare, variabilă, vector sau structură de date sunt folosite adesea ca și cum ar însemna același lucru. Nu înseamnă. Ele se află pe niveluri diferite, iar confuzia dintre niveluri este sursa multor greșeli de începător: o variabilă nu este un tip, un vector nu este o variabilă, o valoare nu are un nume. Schema de mai jos este harta pe care o vom parcurge în această secțiune, concept cu concept.

Trei relații leagă conceptele: o valoare aparține unui tip, o variabilă este exemplar al unui tip, iar un tip compus se construiește din alte tipuri, simple sau compuse (săgeata punctată). Pentru că ingredientele pot fi, la rândul lor, tipuri compuse, construcția se poate relua: așa apar matricea (vector de vectori) sau vectorul de texte.

1.1. De la informație la date

Descrierea editurii pentru volumul 1 din The Art of Computer Programming (Knuth) spune că subiectul capitolului „Information Structures” este reprezentarea informației în calculator și relațiile structurale dintre elementele de date. Wirth, în Algorithms and Data Structures, adaugă o observație care justifică de ce ne ocupăm de tipuri înainte de programare orientată pe obiecte: deciziile despre structurarea datelor nu se pot lua fără să cunoști algoritmii care vor lucra cu ele, iar alegerea algoritmilor depinde la rândul ei de structura datelor. Cu alte cuvinte, reprezentarea datelor nu este un detaliu de declarare, ci jumătate din soluția problemei.

1.2. Tipul de date

Definiția clasică, de curs introductiv, este: un tip de date este o mulțime de valori împreună cu operațiile definite pe acea mulțime (prezentarea de curs a lui M. Minea, UPT). Cardelli și Wegner (1985) tratează la rândul lor tipurile ca mulțimi de valori dintr-un univers și adaugă o a doua față: un tip protejează o reprezentare netipată de utilizări arbitrare sau neintenționate. Pentru tine, merită reținute ambele fețe. Tipul spune ce valori sunt permise și ce operații au sens pe ele, și, totodată, te apără de folosirea greșită a biților din memorie.

Faptul că operațiile aparțin tipului se vede când încerci o operație care nu este definită. Pentru double, operatorul % nu există, iar compilatorul refuză programul înainte să ruleze. Mesajul real al lui g++ 13.3 pentru double b = a % 2; este:

Rolul tipului nu se oprește la a refuza operații. El decide și ce înseamnă o operație: 7 / 2 are valoarea 3 pentru că ambele valori sunt int, iar 7.0 / 2 are valoarea 3.5 pentru că una dintre ele este double. Același simbol, /, face lucruri diferite pe tipuri diferite.

1.3. Variabila

Tipul este un concept; o variabilă este ceva concret din program. În formularea didactică a acestui material, o variabilă este un obiect denumit, de un anumit tip, care ține o valoare din mulțimea acelui tip, valoare care se poate schimba pe parcursul programului. Standardul C++ spune la rândul lui că tipurile descriu obiecte, referințe și funcții, deci tipul este cel care descrie variabila, nu invers.

Anatomia unei declarări cu inițializare
1int 2varsta = 317;
  • 1Tipul – ce fel de valori poate ține
  • 2Numele – cum o regăsești în program
  • 3Valoarea – ce ține acum; se poate schimba
Tip + nume + valoare: orice variabilă le are pe toate trei.

Formularea de mai sus este o formulare didactică a autorului materialului, nu o definiție preluată dintr-o sursă.

Observă cele trei lucruri distincte din schemă: int este tipul, 7 și 9 sunt valori din mulțimea acelui tip, iar x și y sunt variabilele care le țin.

Și în Java și în Python?

În Java, ca în C++, tipul se declară pentru variabilă (int x = 7;). În Python nu se declară niciun tip: x = 7 leagă numele x de un obiect, iar tipul aparține obiectului, nu numelui; același nume poate fi legat mai târziu de un obiect de alt tip (legarea numelor la obiecte este descrisă în Python Tutorial, cap. 9). Ideea schemei rămâne aceeași: tipul este mulțimea de valori și operații, iar valoarea concretă are un tip.

1.4. Tipuri simple și tipuri compuse

Un tip simplu (primitiv) este un element de bază oferit de limbaj, din care se construiesc recursiv tipurile mai complicate (Wikipedia, „Primitive data type”). O valoare a unui tip simplu este o singură „bucată” de informație: un număr, un caracter, o valoare de adevăr. Un tip compus este construit din tipuri simple și din alte tipuri compuse, iar modurile de combinare se numesc, în limbajul curent, structuri de date (Wikipedia, „Data type”). Wirth numește „structuri fundamentale” cele trei principii de construcție din care derivă celelalte: înregistrarea, tabloul de dimensiune fixă și mulțimea.

Pentru M9 ne interesează două dintre ele. Tabloul (vectorul, matricea) grupează valori de același tip și le accesează după număr. Înregistrarea (struct) grupează valori care pot avea tipuri diferite și le accesează după nume. Prima este subiectul restului acestui laborator; a doua este subiectul Laboratorului 2.

⚠️
Atenție la cuvântul „compus”

În manualele de programare, „tip compus” înseamnă, de regulă, tablou sau înregistrare. Standardul C++ folosește același cuvânt într-un sens mai larg: împarte tipurile în fundamentale și compuse, iar în categoria compuselor intră și pointerii, referințele, enumerările, uniunile și funcțiile (C++ draft, [basic.types]; cppreference, std::is_compound). În acest material folosim sensul din manuale. Dacă citești standardul, ține minte diferența.

1.5. Vectorul, matricea și textul: recapitulare

Cele trei forme sunt moduri de a construi un tip compus, nu trei lucruri independente de tipurile pe care le cunoști. Un vector (tablou unidimensional) este un șir de n elemente de același tip, memorate unul după altul și accesate printr-un indice; standardul C++ definește tabloul ca o mulțime nevidă de N subobiecte de același tip, alocate contiguu, numerotate 0, …, N − 1. O matrice este un tablou cu doi indici: linia și coloana. Un text este, în C++, un vector de char.

1.6. Compunerea este recursivă

Cea mai importantă consecință a definiției „tip compus = construit din alte tipuri” este că construcția poate fi reluată: elementele unui tablou pot fi ele însele tablouri sau texte, iar standardul C++ spune explicit că metodele de construire a tipurilor compuse se pot aplica recursiv. Ai folosit deja asta, probabil fără să o numești. Un vector de nume este un vector în care fiecare element este un text, adică un vector de char.

C++ – un vector de 3 texte, fiecare de cel mult 19 caractere
#include <iostream>
using namespace std;

int main() {
    char nume[3][20] = {"Ana", "Bogdan", "Cezar"};
    cout << nume[1] << " " << nume[1][0] << endl;
    return 0;
}
Se afișează
Bogdan B

Expresia nume[1] este un text întreg („Bogdan”), iar nume[1][0] este un singur caracter („B”). Același tip, char, apare la trei niveluri: caracterul, textul, vectorul de texte. Tabelul de mai jos ordonează câteva compuneri după ce poți construi cu ele; ultimele două cer un tip pe care nu îl avem încă, structura, și sunt anunțul Laboratorului 2.

1.7. Criterii de clasificare: proprietăți, nu categorii

În manuale și materiale de curs, structurile de date se clasifică după câteva criterii. Cele mai întâlnite sunt omogene / eterogene (toate componentele au același tip sau nu), statice / dinamice (dimensiunea este fixă sau se poate schimba în timpul execuției) și liniare / neliniare (componentele sunt aranjate într-un șir sau într-o altă relație, de exemplu arbore sau graf). Esențial este că acestea sunt proprietăți ale unui tip compus, nu categorii de același rang cu vectorul sau structura: o aceeași structură poate avea simultan mai multe dintre ele (o sursă notează explicit că o structură poate aparține mai multor categorii deodată).

Definițiile criteriilor sunt, în general, de acord, dar exemplele diferă: unele pagini consideră stivele și cozile statice, altele, dinamice, după implementare; unele pagini numesc arborii și grafurile eterogene. Criteriile static / dinamic și liniar / neliniar sunt aici doar numite; le vei dezvolta la structurile de date dinamice.

2. De la realitate la reprezentare

Programul nu lucrează cu lucrurile din realitate, ci cu reprezentări ale lor: valori memorate în variabile, vectori, matrice sau, mai târziu, structuri. A reprezenta un lucru înseamnă să alegi, din tot ce se poate spune despre el, ce informații păstrezi și în ce formă le memorezi, astfel încât programul să poată răspunde la întrebarea pentru care a fost scris. Ce nu păstrezi, programul nu poate afla, iar ce se poate calcula din ce ai păstrat nu trebuie memorat încă o dată.

Formulare didactică a autorului materialului, nu o definiție preluată dintr-o sursă.

💡
Modelul nu este realitatea

Un elev real are sute de caracteristici: înălțime, culoarea ochilor, prieteni, hobby-uri. Pentru un catalog contează doar numele, clasa și notele. Ce este relevant se stabilește după întrebarea la care trebuie să răspundă programul, nu după lucrul în sine: pentru alt program (o echipă de fotbal, de exemplu), aceleași persoane ar fi descrise prin alte caracteristici.

2.1. Cinci pași de la realitate la reprezentare

  1. Alege lucrul și întrebarea. Ce lucru din realitate descrii și la ce întrebare trebuie să răspundă programul (media clasei? locurile libere? elevul cu nota maximă?).
  2. Alege informațiile relevante. Păstrează numai ce trebuie ca să răspunzi la întrebare. Ce se poate calcula din alte informații (vârsta din data nașterii, media din note) nu se memorează separat.
  3. Alege tipul fiecărei informații. Pentru fiecare informație stabilește tipul simplu și domeniul valorilor (partea de tip din hartă): un număr de pagini este un întreg pozitiv, o notă este un întreg între 1 și 10, un număr de telefon este text.
  4. Alege forma de grupare. O singură informație: variabilă. Mai multe valori de același tip pe un rând: vector. Un tabel de valori de același tip: matrice. Informații de tipuri diferite despre același lucru: structură (Laboratorul 2). Mai multe astfel de lucruri: vector de structuri.

3. Erori frecvente

Eroarea 1 – Indice în afara vectorului

Pentru un vector cu 5 elemente, indicii valizi sunt 0 … 4. Accesarea lui v[5] este o greșeală în toate limbajele, dar fiecare reacționează diferit. În C++ programul se compilează și rulează; comportamentul este nedefinit, adică standardul nu promite niciun rezultat. În Java și în Python programul se oprește cu un mesaj clar.

Java – la rulare
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 5
	at IndexJava.main(IndexJava.java:4)
Python – la rulare
    print(v[5])
          ~^^^
IndexError: list index out of range

În C++ nu apare niciun mesaj: citirea lui v[5] dă o valoare oarecare din memorie, iar o scriere la acel indice poate strica alte date sau poate opri programul. Tocmai pentru că nu există o avertizare, verificarea limitelor ține de programator: o buclă pentru n elemente are condiția i < n, nu i <= n.

Eroarea 2 – Vector local neinițializat

Un vector declarat în main fără valori (int a[5];) conține valori oarecare rămase în memorie. Când trebuie să pornească de la zero, de exemplu pentru contoare, scrie explicit = {0}.

C++ – corect și incorect
int a[5];          // valori nedefinite: nu citi înainte să scrii
int b[5] = {0};   // toate elementele sunt 0

Eroarea 3 – Atribuirea unui vector întreg

Un vector nu se copiază cu b = a;; copierea se face element cu element, cu o buclă. Încercarea este refuzată la compilare. Mesajul real al lui g++ 13.3:

g++
atrib.cpp:4:7: error: invalid array assignment

Eroarea 4 – Confuzia dintre indice și poziție

Când enunțul numără pozițiile de la 1, elementul de pe poziția p este v[p − 1]. Folosirea directă a lui p ca indice produce un rezultat greșit fără nicio eroare de compilare. Aceeași confuzie apare la reprezentare: dacă modelul spune „testul 1 este indicele 0”, orice program trebuie să respecte convenția.

8Un program memorează ora ca trei întregi (h, m, s), iar altul ca un singur întreg (secunde de la miezul nopții). Care reprezentare e mai comodă pentru a afișa ora? Dar pentru a calcula diferența a două momente? (propus de autor)

Exercițiul 1 — două variabile

Soluție: b primește o copie a valorii lui a (5). Apoi a devine 7, dar b rămâne 5: sunt două variabile distincte. Se afișează 7 5.

Exercițiul 2 — sumă pe poziții impare
C++
int v[6] = {4, 7, 2, 9, 5, 1};
int s = 0;
for (int i = 0; i < 6; i += 2) {
    s += v[i];
}
cout << s;

Soluție: i ia valorile 0, 2 și 4, deci se adună v[0] + v[2] + v[4] = 4 + 2 + 5. Atenție: indicii 0, 2, 4 sunt pozițiile 1, 3, 5. Se afișează 11.

Exercițiul 3 — diagonala unei matrice
C++
int m[2][3] = {{1, 2, 3}, {4, 5, 6}};
int s = 0;
for (int i = 0; i < 2; i++) {
    for (int j = 0; j < 3; j++) {
        if (i == j) {
            s += m[i][j];
        }
    }
}
cout << s << " " << m[1][2];

Soluție: Se adună doar elementele cu indicii egali: m[0][0] = 1 și m[1][1] = 5, deci s = 6. Al doilea număr este m[1][2], adică linia 1, coloana 2, valoarea 6. Se afișează 6 6.

Exercițiul 4 — modificarea unui text
C++

cout << s << " " << strlen(s);

Soluție: Un text C++ este un vector de char, deci se poate modifica pe loc: s[1] devine X. Lungimea rămâne 3, pentru că terminatorul '\0' este tot pe poziția 3. Se afișează aXc 3.

Exercițiul 5 — maxim cu poziție și egalități
C++
int v[5] = {3, 5, 4, 5, 1};
int poz = 0;
for (int i = 1; i < 5; i++) {
    if (v[i] >= v[poz]) {
        poz = i;

Întrebări de autoevaluare

1. Ce este un tip de date? Dă o definiție și un exemplu de operație care nu aparține unui tip.

Un tip de date este o mulțime de valori împreună cu operațiile definite pe ea. Exemplu: % nu este definit pe double, iar g++ refuză programul care îl folosește.

2. Care este diferența dintre un tip, o valoare și o variabilă? Explică pe int x = 7;.

int este tipul (mulțimea de valori și operații), 7 este o valoare din acea mulțime, iar x este variabila: un obiect denumit, de tipul int, care ține în acest moment valoarea 7. Variabila își poate schimba valoarea; tipul nu se schimbă.

3. Ce este un tip simplu și ce este un tip compus? Dă câte două exemple.

Un tip simplu este un element de bază al limbajului (int, double, bool, char) și are o singură valoare. Un tip compus este construit din alte tipuri (vector, matrice, text). În sensul standardului C++, „compus” are un sens mai larg decât în manuale.

4. Cum se construiesc vectorul, matricea și textul din tipuri mai simple?

Vectorul grupează n elemente de același tip, accesate printr-un indice. Matricea este un vector ale cărui elemente sunt la rândul lor vectori (accesată cu doi indici). Textul este, în C++, un vector de char terminat cu '\0'. Toate sunt cazuri ale aceleiași reguli: un tip compus se construiește din alte tipuri, recursiv.

5. Ce înseamnă că omogen / eterogen, static / dinamic și liniar / neliniar sunt proprietăți, nu categorii?

Sunt criterii independente, care descriu o structură din puncte de vedere diferite; aceeași structură poate avea mai multe dintre ele simultan. Un vector C++ este, de exemplu, omogen și de dimensiune fixă. Nu sunt categorii de același rang cu „vector” sau „struct”, care sunt moduri de construire.

6. Spune cei cinci pași pentru a trece de la un lucru din realitate la o reprezentare.

1) lucrul și întrebarea; 2) informațiile relevante (ce se calculează nu se memorează); 3) tipul și domeniul fiecărei informații; 4) forma de grupare (variabilă, vector, matrice, ...); 5) verificarea: poți răspunde la întrebare din ce ai reprezentat?

7. Ce este o convenție de reprezentare? Dă un exemplu.

Este regula care spune ce înseamnă o poziție dintr-un vector sau o matrice. Exemplu: în note[5], indicele i corespunde testului cu numărul i + 1; într-o matrice de prezență, linia este elevul, iar coloana este ora. Convenția nu apare în cod, de aceea trebuie respectată peste tot.

8. De ce nu se memorează o informație care se poate calcula?

Pentru că, dacă o păstrezi separat, poate ajunge în dezacord cu informațiile din care se calculează (de exemplu vârsta față de data nașterii) și programul devine inconsistent.

9. Prin ce diferă domeniul unei informații de tipul ei? Dă un exemplu.

Tipul este mulțimea tuturor valorilor pe care le acceptă limbajul; domeniul este mulțimea valorilor cu sens pentru informația respectivă. O notă are domeniul {1, …, 10}, dar tipul int acceptă și −5 sau 100. Tipul singur nu apără domeniul.

10. De ce ora poate fi reprezentată în două feluri? Când alegi unul sau celălalt?

Pentru că aceeași realitate admite mai multe reprezentări corecte. Trei întregi (ore, minute, secunde) sunt comode la afișare; un singur întreg (secunde de la miezul nopții) este comod la comparații și diferențe. Alegi după operația mai frecventă și nu le păstrezi pe ambele.

11. Ce eroare apare în C++ la v[5] pentru un vector cu 5 elemente? Cum reacționează Java și Python?

În C++ nu apare nicio eroare de compilare și nicio verificare la rulare: comportamentul este nedefinit. Java oprește programul cu ArrayIndexOutOfBoundsException, iar Python, cu IndexError.

12. De ce nu ajung vectorii și matricele pentru a reprezenta un student cu nume și notă?

Pentru că elementele lor sunt de același tip, iar un student are informații de tipuri diferite. Soluția cu doi vectori paraleli (nume[i] și nota[i]) merge doar prin convenția că același indice înseamnă același student; legătura nu este înscrisă în program și se strică ușor. Cele mai importante idei din acest laborator

Citește lista de mai jos după ce ai rezolvat exercițiile; fiecare punct trimite la o secțiune din tabul Curs.

  1. Tipul este o mulțime de valori împreună cu operațiile permise; valoarea este un element al lui; variabila este un obiect denumit, de un tip, care ține o valoare. Sunt trei niveluri diferite.
  2. Tipurile simple (int, double, bool, char) au o singură valoare; tipurile compuse se construiesc din alte tipuri.
  3. Vectorul, matricea și textul sunt moduri de a construi un tip compus din elemente de același tip. Matricea este un vector de vectori, iar un text este un vector de char.
  4. Compunerea este recursivă: elementele unui vector pot fi vectori sau texte (char nume[3][20]). Vectorul de structuri și structura cu vector urmează în Laboratorul 2.
  5. Omogen / eterogen, static / dinamic, liniar / neliniar sunt proprietăți ale unei structuri, nu categorii de același rang cu vectorul sau structura.
  6. Cei cinci pași ai reprezentării: lucrul și întrebarea, informațiile relevante, tip și domeniu, formă de grupare, verificare. Ce se poate calcula nu se memorează.
  7. O reprezentare include o convenție (ce înseamnă un indice) și poate avea alternative corecte; alegi după ce faci mai des cu informația.
  8. Domeniul unei informații poate fi mai mic decât tipul ei; tipul singur nu apără domeniul.
  9. C++ nu verifică indicii: v[n] este comportament nedefinit; Java și Python semnalează eroare.
