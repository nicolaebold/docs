Introducere

În sesiunea anterioară ai lucrat cu date, variabile, constante, tipuri de date și operatori. Ai văzut cum pot fi memorate valori în program și ce operații pot fi efectuate asupra lor.

Totuși, în programele reale nu folosim operatorii izolat. Ei sunt combinați cu valori, constante și variabile pentru a forma expresii. De exemplu, dacă avem int a = 10; și int b = 3;, operatorul + poate fi utilizat în expresia a + b. Expresia este evaluată, iar în acest caz produce valoarea 13. În mod asemănător, expresia a > b nu produce un rezultat numeric obișnuit, ci un rezultat logic: true sau false.

Ideea principală

Un operator precizează ce operație trebuie realizată, iar o expresie precizează asupra căror valori se aplică acea operație și produce un rezultat.

Expresiile reprezintă una dintre componentele fundamentale ale unui limbaj de programare. Ele apar aproape peste tot într-un program: în calcule, în atribuiri, în comparații și, așa cum vei vedea în sesiunile următoare, în condițiile utilizate pentru luarea deciziilor.

Concepte fundamentale

Un operator precizează ce operație trebuie realizată, dar pentru ca operația să poată fi efectuată avem nevoie și de valorile asupra cărora acționează acesta. Aceste valori se numesc operanzi.

C++
a + b

Operatorul este +, iar a și b sunt operanzii săi.

Definiție

Un operand este o valoare, o variabilă, o constantă sau chiar o altă expresie asupra căreia acționează un operator. O expresie este o construcție a limbajului formată din unul sau mai mulți operanzi și operatori și care poate fi evaluată pentru a obține un rezultat.

Expresiile pot fi foarte simple (5, x, a + b) sau pot fi formate din alte expresii:

C++
a * (b + 1)

Aici, operatorul * are doi operanzi: variabila a și expresia b + 1. La rândul său, expresia b + 1 este formată din operatorul + și operanzii b și 1. Prin urmare, o expresie complexă poate fi privită ca o construcție formată din expresii mai simple.

O expresie nu este obligatoriu un calcul aritmetic

De exemplu, varsta >= 18 este tot o expresie, chiar dacă rezultatul său nu este o valoare numerică obișnuită, ci o valoare logică (true sau false).

O expresie este utilizată pentru a determina o valoare. Procesul prin care se determină această valoare se numește evaluarea expresiei. Dacă într-o expresie apar variabile, rezultatul depinde de valorile pe care acestea le au în momentul evaluării — expresia descrie calculul care trebuie realizat, nu o valoare fixă.

Legătura dintre concepte

O expresie este formată din operanzi și operatori. Expresia este evaluată, iar evaluarea produce un rezultat. Rezultatul are întotdeauna un anumit tip de date: operanzi + operatori → expresie → evaluare → rezultat.

Expresii aritmetice

O expresie aritmetică este o expresie utilizată pentru efectuarea calculelor numerice. Poate conține literali, variabile, constante, mai mulți operatori, paranteze și alte expresii.

Operatorul % are un rol special: determină restul împărțirii întregi și este utilizat numai cu valori de tip întreg. De exemplu, 7 % 3 produce valoarea 1, deoarece 7 = 2 · 3 + 1.

C++

Observă că a / b produce valoarea 2, nu 2.333..., deoarece ambii operanzi sunt întregi — vom analiza separat împărțirea întreagă în secțiunea despre tipuri.

Evaluarea în scurt-circuit

C++ (la fel ca Java) evaluează expresiile && și || „în scurt-circuit": operanzii sunt evaluați de la stânga la dreapta, iar evaluarea se oprește imediat ce rezultatul final poate fi determinat, fără a mai calcula operandul din dreapta.

C++
// daca x este 0, x != 0 este false, deci intreaga expresie
// este garantat false - a doua parte nici nu se mai evalueaza
(x != 0) && (10 / x > 2)

Aici, dacă x este 0, prima condiție (x != 0) este deja false, iar && are nevoie ca ambele condiții să fie adevărate — rezultatul e sigur false, indiferent ce ar da a doua parte. C++ profită de acest lucru și nu mai evaluează deloc 10 / x, evitând astfel o împărțire la zero. Regula simetrică există și pentru ||: dacă prima condiție este deja true, a doua nu mai este evaluată, pentru că rezultatul e oricum true.

Diferență de comportament în Python

Python evaluează and/or tot în scurt-circuit, dar cu o particularitate: nu returnează neapărat True/False, ci valoarea efectivă a unuia dintre cei doi operanzi. De exemplu, 0 or "implicit" returnează șirul "implicit" (nu True), pentru că 0 este considerat fals, iar Python evaluează și întoarce al doilea operand. Acesta e un comportament specific limbajului, dincolo de scopul acestei sesiuni — în C++, rezultatul lui &&/|| este întotdeauna strict bool.

Reguli de evaluare a expresiilor

Atunci când o expresie conține mai mulți operatori, apare o întrebare importantă: în ce ordine sunt efectuate operațiile? Într-o expresie precum a + b * c există doi operatori diferiți. Pentru a determina rezultatul corect, limbajul utilizează reguli de prioritate și asociativitate. Parantezele pot fi utilizate pentru a modifica sau clarifica ordinea de evaluare.

Prioritatea operatorilor

Prioritatea operatorilor stabilește care operatori se aplică mai întâi atunci când într-o expresie apar operatori diferiți — la fel ca în matematică, unde 2 + 3 · 4 = 2 + 12 = 14, nu 5 · 4 = 20. Pentru operatorii utilizați în această etapă a cursului, putem folosi următoarea ordine simplificată (un nivel mai mic înseamnă prioritate mai mare):

De exemplu, a + b * c este interpretată ca a + (b * c), iar a > b && c > d este interpretată ca (a > b) && (c > d), deoarece operatorii relaționali au prioritate mai mare decât operatorul logic &&.

Important

Prioritatea operatorilor nu stabilește „care operator este mai important", ci doar modul în care sunt grupate operațiile într-o expresie. Este util să cunoști regulile de bază, dar nu este recomandat să memorezi mecanic toate nivelurile de prioritate. Dacă expresia devine greu de citit, folosește paranteze.

Asociativitatea operatorilor

Ce se întâmplă dacă într-o expresie apar mai mulți operatori cu aceeași prioritate? În acest caz intervine asociativitatea — regula care stabilește modul în care sunt grupate operațiile care folosesc operatori cu același nivel de prioritate. Pentru majoritatea operatorilor aritmetici din această sesiune, asociativitatea este de la stânga la dreapta.

De exemplu, 20 - 5 - 3 este interpretată ca (20 - 5) - 3: mai întâi 20 − 5 = 15, apoi 15 − 3 = 12. Rezultatul este 12, nu 18 (care ar rezulta din 20 − (5 − 3)). Similar, 24 / 6 * 2 se grupează (24 / 6) * 2 = 4 · 2 = 8.

Prioritate vs. asociativitate — nu sunt același lucru

Prioritatea este utilizată când operatorii au niveluri diferite. Asociativitatea este utilizată când operatorii au aceeași prioritate. De exemplu, în 10 + 8 / 4 * 2: întâi analizăm prioritatea → 10 + (8 / 4 * 2); apoi, cum / și * au aceeași prioritate, aplicăm asociativitatea de la stânga la dreapta → 10 + ((8 / 4) * 2). Obținem 8/4=2, 2·2=4, 10+4=14.

Rolul parantezelor

Parantezele permit programatorului să stabilească explicit modul în care trebuie grupată o expresie. De exemplu, 2 + 3 * 4 produce 14, în timp ce (2 + 3) * 4 produce 20. Două expresii care conțin aceleași valori și aceiași operatori pot produce rezultate diferite dacă gruparea este diferită.

Parantezele pot fi utilizate în două scopuri principale: pentru a modifica ordinea implicită stabilită prin prioritatea operatorilor, și pentru a clarifica intenția programatorului, chiar dacă ordinea ar putea fi determinată și fără ele. De exemplu, pret * cantitate - reducere + transport este corectă, dar mai ușor de înțeles ca (pret * cantitate) - reducere + transport. La fel, (varsta >= 18) && (varsta <= 65) face imediat vizibil faptul că sunt combinate două comparații, deși parantezele nu sunt obligatorii aici.

Recomandare

Nu folosi paranteze numai atunci când sunt obligatorii — folosește-le și atunci când fac expresia mai ușor de citit și reduc riscul unei interpretări greșite. Un program trebuie să fie corect, dar și clar. Trebuie evitat însă și excesul: ((((a + b)))) este corect sintactic, dar nu aduce nicio informație suplimentară față de a + b.

Evaluarea unei expresii pas cu pas

Pentru a determina corect rezultatul unei expresii, este util să o evaluăm în mai multe etape: (1) identificăm parantezele; (2) identificăm operatorii și nivelurile lor de prioritate; (3) aplicăm asociativitatea acolo unde este necesar; (4) efectuăm operațiile în ordinea stabilită; (5) determinăm rezultatul final.

Pentru int a = 4; int b = 3; int c = 2; și expresia a + b * c: operatorul * are prioritate mai mare, deci a + (b * c) → b·c = 6 → 4 + 6 = 10. Pentru aceleași valori, expresia (a + b) * c evaluează întâi paranteza (4+3=7), apoi 7·2=14 — rezultatul este 14, nu 10.

Evaluare pas cu pas — 10 + 6 / 3 * 2
10 + 6 / 3 * 2
→ 10 + (6 / 3) * 2    // / si * au prioritate mai mare
→ 10 + 2 * 2          // 6/3 = 2
→ 10 + 4              // 2*2 = 4
→ 14

Aceeași metodă se aplică și expresiilor logice: pentru 5 > 3 && 10 != 4, evaluăm întâi comparațiile (5>3 → true, 10≠4 → true), apoi combinăm true && true → true. Pentru 5 > 8 || 10 == 10: 5>8 → false, 10==10 → true, deci false || true → true.

Metodă de lucru

Atunci când o expresie pare complicată, nu încerca să determini direct rezultatul final. Redu expresia treptat: expresie inițială → expresie simplificată → expresie simplificată → rezultat. Această metodă va fi utilizată și în exercițiile de code tracing.

Tipuri, conversii și modificarea valorilor

Expresiile nu produc doar o valoare — rezultatul lor are și un anumit tip de date. Tipul rezultatului este important deoarece poate influența modul în care este efectuat calculul, valorile care pot fi reprezentate, operațiile care pot fi realizate ulterior și eventualele conversii necesare. Aceste idei apar în multe limbaje de programare, dar regulile concrete pot diferi de la unul la altul; vom folosi C++ ca limbaj principal și vom compara, acolo unde e relevant, cu Python și Java.

Tipul rezultatului unei expresii

Tipul rezultatului depinde de tipurile operanzilor, de operatorul utilizat, de regulile limbajului și de eventualele conversii de tip. O expresie aritmetică poate produce o valoare întreagă sau reală, iar o expresie relațională produce, în mod obișnuit, o valoare logică.

Concluzie

Conceptul de împărțire este general, dar operatorii și regulile de evaluare sunt stabilite de fiecare limbaj de programare. Nu presupune că aceeași expresie produce același rezultat în toate limbajele.

Conversii de tip

Expresii de atribuire

Atribuirea reprezintă asocierea sau memorarea unei valori într-o variabilă: expresie → valoare → variabilă. De exemplu, în x = 5 + 3;, mai întâi este evaluată expresia 5 + 3 = 8, iar apoi valoarea este memorată în x. Vom utiliza atribuirea în forma sa simplă, cu ordinea: evaluare → rezultat → atribuire.

În C++ și Java există și diferența dintre forma prefixată și cea postfixată atunci când operatorul face parte dintr-o expresie mai mare:

C++
int x = 5;
int y = x++;  // y = 5, apoi x devine 6 (postfixat: se foloseste intai valoarea veche)

int x2 = 5;
int y2 = ++x2; // x2 devine 6, apoi y2 = 6 (prefixat: se foloseste valoarea noua)

Python nu are un echivalent direct pentru această construcție. Pentru programele introductive vom prefera formele simple și clare și vom evita expresiile în care aceeași variabilă este incrementată sau decrementată de mai multe ori.

Urmărirea valorilor variabilelor

Urmărirea valorilor variabilelor nu este o particularitate a C++ — este o metodă generală de analiză a unui program. Ideea este simplă: urmărim, în ordinea execuției, modul în care se modifică valorile variabilelor.

Instrucțiunex
int x = 5;5
x = x + 2;7
x *= 3;21
Metodă generală de code tracing

Indiferent de limbaj: (1) urmărește instrucțiunile în ordinea în care sunt executate; (2) determină valoarea expresiei; (3) observă dacă valoarea unei variabile se modifică; (4) notează noua valoare; (5) utilizează această valoare în pașii următori. Tehnica este utilă atât pentru înțelegerea programelor, cât și pentru identificarea erorilor.

Construirea și utilizarea corectă a expresiilor

Până acum ai analizat expresii deja scrise și ai urmărit modul în care acestea sunt evaluate. În practică, programatorul trebuie să facă și procesul invers: pornind de la o formulă, o cerință sau o situație reală, trebuie să construiască expresia care reprezintă corect problema. Acest proces presupune: identificarea valorilor necesare, identificarea operațiilor, stabilirea ordinii corecte, alegerea operatorilor potriviți, verificarea tipurilor de date și scrierea expresiei într-o formă clară și corectă.

Transcrierea formulelor matematice

O formulă matematică nu poate fi copiată întotdeauna direct într-un limbaj de programare. În matematică, înmulțirea este adesea implicită (2x, 3(a+b)); într-un limbaj de programare, operatorul de înmulțire trebuie scris explicit.

Parantezele sunt esențiale atunci când numărătorul sau numitorul unei fracții este o sumă: (x + 1) / (2 * y), nu (x + 1) / 2y (invalid). Formula mediei a trei valori m = (a+b+c)/3 devine (a + b + c) / 3; dacă valorile sunt întregi și dorim un rezultat real, scriem (a + b + c) / 3.0 (în Python, / produce deja o împărțire reală).

Expresii mixte

O expresie poate combina operatori din categorii diferite — de exemplu calcule aritmetice, comparații și operații logice. a + b > c combină o operație aritmetică (a + b) cu o comparație (>). O expresie mai complexă precum a + b > 10 && c != 0 se înțelege mai ușor scrisă (a + b > 10) && (c != 0): mai întâi se calculează a + b, rezultatul se compară cu 10, apoi se evaluează c != 0, iar cele două rezultate logice sunt combinate prin &&.

Construirea expresiilor pentru probleme concrete

Atunci când rezolvi o problemă, nu este recomandat să începi direct cu scrierea expresiei. Poți utiliza următorul model: (1) identifici datele de intrare; (2) identifici rezultatul dorit; (3) stabilești relația matematică sau logică; (4) alegi variabilele și tipurile lor; (5) construiești expresia; (6) verifici rezultatul cu valori de test.

Un exemplu clasic: dorim o expresie adevărată dacă o vârstă este cuprinsă între 18 și 65 de ani, inclusiv. Matematic scriem 18 ≤ varsta ≤ 65, dar în C++ și Java nu putem scrie relația exact așa — trebuie construite două comparații: (varsta >= 18) && (varsta <= 65). (În Python este posibilă și forma 18 <= varsta <= 65 — un exemplu bun în care aceeași relație matematică se exprimă diferit de la un limbaj la altul.)

Întrebare de verificare

Înainte de a considera o expresie corectă, întreabă-te: ce valori intră în calcul? ce rezultat trebuie să obțin? ce operatori reprezintă relația? ordinea operațiilor este corectă? tipurile de date permit rezultatul dorit?

Claritatea expresiilor contează la fel de mult ca acuratețea lor. O expresie precum a+b*c-d/e este mai ușor de citit scrisă a + b * c - d / e, iar dacă relațiile dintre operații sunt importante, paranteze suplimentare pot ajuta cititorul să identifice rapid structura, chiar dacă nu sunt strict obligatorii din punctul de vedere al priorității.

Anatomia unei expresii mixte

Considerăm expresia pret * cantitate >= 100 && cantitate > 0, care ar putea verifica dacă o comandă îndeplinește un prag minim de valoare și are o cantitate pozitivă:

C++ – Adnotat
pret * cantitate >= 100 && cantitate > 0
// ① pret * cantitate       - se calculeaza intai (prioritate cea mai mare)
// ② (pret*cantitate) >= 100 - rezultatul e comparat cu 100 (bool)
// ③ cantitate > 0           - a doua comparatie, independenta (bool)
// ④ (2) && (3)              - cele doua rezultate logice se combina

Structura calcul aritmetic → comparație → combinare logică este un tipar pe care îl vei regăsi în aproape orice condiție mai complexă pe care o vei scrie.

Ce se întâmplă dacă…?

… eliminăm parantezele de la calculul mediei?
C++
// GRESIT - fara paranteze:
double media = nota1 + nota2 + nota3 / 3;
// Se evalueaza: nota1 + nota2 + (nota3 / 3)
// 8.5 + 9.0 + (7.5/3) = 8.5 + 9.0 + 2.5 = 20.0 -- GRESIT!

// CORECT - cu paranteze:
double media = (nota1 + nota2 + nota3) / 3;
// (8.5 + 9.0 + 7.5) / 3 = 25.0 / 3 = 8.333

Împărțirea are prioritate mai mare decât adunarea, deci fără paranteze se împarte mai întâi ultimul operand la 3.

… folosim || în loc de && pentru un interval?
C++
// Dorim: x este intre 1 si 10
// GRESIT:
(x >= 1) || (x <= 10)   // adevarata pentru aproape orice x!

// CORECT:
(x >= 1) && (x <= 10)

Cu ||, e suficient ca una dintre condiții să fie adevărată — iar orice număr este fie >= 1, fie <= 10 (sau ambele), deci expresia devine practic mereu adevărată.

… împărțim două int-uri și vrem rezultat cu zecimale?
C++
int a = 7, b = 2;

int rez1 = a / b;          // 3 - impartire intreaga
double rez2 = a / b;       // 3 - calculul e int, doar rezultatul e stocat in double
double rez3 = 7.0 / b;     // 3.5 - literalul 7.0 forteaza impartire reala

Tipul rezultatului unei operații aritmetice este determinat de tipurile operanzilor implicați în calcul, nu de tipul variabilei în care este stocat rezultatul.

Vezi rezolvarea

Problemă: fără paranteze, doar b este împărțit la 2, apoi rezultatul se adună la a. Corect: double m = (a + b) / 2.0;

Întrebări de autoevaluare

1. Ce este o expresie și din ce este formată?

O expresie este o construcție a limbajului formată din unul sau mai mulți operanzi și operatori, care poate fi evaluată pentru a produce un rezultat.

2. Care este diferența dintre un operand și un operator?

Operatorul precizează ce operație trebuie realizată (ex: +); operandul este valoarea, variabila sau expresia asupra căreia acționează operatorul (ex: a și b în a + b).

3. Ce afișează: int a = 7; int b = 2; cout << a / b;

3. Împărțirea a două int-uri produce int — zecimalele se pierd (trunchiere, nu rotunjire).

4. Cum obții rezultat cu zecimale la împărțirea 7 / 2?

Cel puțin un operand implicat în calcul trebuie să fie double: 7.0 / 2 sau 7 / 2.0.

5. Ce este restul împărțirii întregi și cum se calculează?

Restul rămas după împărțirea întreagă a doi întregi, obținut cu operatorul %. 7 % 3 = 1 (deoarece 7 = 2×3 + 1).

6. Care este diferența dintre prioritate și asociativitate?

Prioritatea decide ce operator se aplică mai întâi când operatorii dintr-o expresie au niveluri diferite (ex: * înaintea lui +). Asociativitatea decide ordinea de grupare când operatorii au aceeași prioritate (majoritatea, de la stânga la dreapta).

7. De ce sunt utile parantezele, dacă prioritatea operatorilor deja stabilește o ordine?

Parantezele pot schimba explicit ordinea implicită dată de prioritate, și pot face o expresie mai clară pentru cititor chiar și atunci când nu sunt strict necesare pentru rezultat.

8. Care este diferența dintre = și == în C++?

= este operatorul de atribuire — pune o valoare într-o variabilă. == este operatorul de comparație — verifică dacă două valori sunt egale și produce un rezultat bool, fără să modifice nimic.

9. Ce valoare produce (x >= 1) || (x <= 10), pentru orice x, și de ce e o capcană frecventă?

Este practic mereu true, pentru că orice număr este fie ≥1, fie ≤10 (sau ambele). Capcana apare când se dorea de fapt un interval (&&), nu o alternativă largă (||).

10. Ce afișează: int x = 5; int y = x++; int z = ++x;

y = 5 (postfixat: se folosește valoarea veche, apoi x devine 6), z = 7 (prefixat: x devine 7, apoi se folosește valoarea nouă).

11. Ce este o conversie de tip implicită și ce este una explicită?

Conversia implicită este realizată automat de limbaj (ex: double b = a;, cu a întreg). Conversia explicită este cerută direct de programator (ex: (double)a sau static_cast<double>(a) în C++).

12. De ce 7 / 2 dă rezultate diferite în C++ și în Python 3?

În C++, dacă ambii operanzi sunt int, / face împărțire întreagă (7/2=3). În Python 3, / face întotdeauna împărțire reală (7/2=3.5); pentru împărțire întreagă, Python are operatorul separat //.

13. Ce greșeală conține: double media = a + b + c / 3.0;?

Lipsesc parantezele — se calculează a + b + (c/3.0), nu media celor trei. Corect: double media = (a + b + c) / 3.0;

Rezumat – De reținut

Cele mai importante idei din această sesiune
  1. O expresie este formată din operanzi și operatori și, prin evaluare, produce un rezultat care are întotdeauna un anumit tip de date.
  2. Expresiile pot fi aritmetice (produc un număr), relaționale sau logice (produc true/false).
  3. Prioritatea stabilește ce operator se aplică mai întâi când operatorii diferă; asociativitatea stabilește ordinea când au aceeași prioritate.
  4. Parantezele controlează și clarifică ordinea de evaluare — folosește-le pentru claritate, nu te baza doar pe memorarea priorităților.
  5. Împărțirea a două int-uri produce int (trunchiere); pentru rezultat real, cel puțin un operand trebuie double.
  6. Operatorul % se folosește doar cu operanzi întregi și dă restul împărțirii.
  7. = este atribuire, == este comparație — confundarea lor produce bug-uri subtile.
  8. Conversiile de tip pot fi implicite (automate) sau explicite (cerute de programator), și pot pierde informație (trunchiere).
  9. Atribuirea compusă (+=, -= etc.) și incrementarea/decrementarea (++, --) sunt prescurtări pentru operații frecvente.
  10. O formulă matematică nu se copiază direct în cod — înmulțirea trebuie scrisă explicit, iar numărătorii/numitorii compuși au nevoie de paranteze.
  11. Date, variabile, tipuri, operatori și reguli de evaluare sunt concepte universale de programare — C++, Python și Java le exprimă prin sintaxe diferite, dar ideea rămâne aceeași.
  12. Folosirea practică a expresiilor logice pentru ca un program să ia decizii (if) este subiectul sesiunii următoare.
