De la instrucțiuni cotidiene la algoritm

Înainte de orice noțiune tehnică, este util să înțelegem ce înseamnă să dai instrucțiuni precise. Gândește-te la o situație simplă: dacă îi spui unui coleg "fă-mi o cafea", sunt șanse mari să înțeleagă ce trebuie să facă. Dacă transmiți exact aceeași instrucțiune unui calculator, vei întâmpina o problemă imediată. Care este diferența?

Un om folosește experiență, context și presupuneri. Știe ce este o cafea, cunoaște contextul, poate completa informațiile lipsă și poate întreba dacă nu înțelege ceva. Un calculator nu poate face nimic din acestea. El are nevoie de instrucțiuni formulate precis, fără ambiguitate, specificate complet.

Analogia rețetei

Care dintre aceste instrucțiuni este mai precisă?
(1) Fă un sandviș.
(2) Ia două felii de pâine, așază o felie de brânză între ele și pune sandvișul pe farfurie.
A doua formulare este mult mai apropiată de modul algoritmic de descriere a unei activități. Nu presupune nimic; specifică toate acțiunile și ordinea lor.

Ce este un algoritm?

Un algoritm este o succesiune finită și bine precizată de pași, utilizată pentru rezolvarea unei probleme. Această definiție conține trei caracteristici esențiale:

  • Finită – algoritmul are un număr determinat de pași; nu poate continua la infinit
  • Bine precizată – fiecare pas este clar și neambiguu; oricine (sau orice mașinărie) urmărind pașii va ajunge la același rezultat
  • Rezolvă o problemă – există un punct de start, date de intrare, operații de prelucrare și un rezultat
Problemă→ Pași de rezolvare→ Algoritm→ Program

Un algoritm poate fi exprimat în limbaj natural, în pseudocod sau în diagramă înainte de a fi tradus într-un limbaj de programare. Gândirea algoritmică – capacitatea de a descompune o problemă în pași precisi și ordonați – este competența fundamentală pe care o formezi prin studiul programării.

Concluzia esențială

Calculatorul are nevoie de instrucțiuni formulate precis. Orice program este, la bază, o traducere a unui algoritm în instrucțiuni pe care sistemul de calcul le poate executa.

Ce este un calculator?

Dacă avem o succesiune precisă de instrucțiuni, cineva trebuie să le execute. Acel "cineva" este sistemul de calcul – calculatorul.

Un calculator (sistem de calcul) este un sistem capabil să primească, să păstreze și să prelucreze informații conform unor instrucțiuni. Din perspectiva programatorului, putem privi sistemul de calcul prin două componente mari: hardware și software.

  • Hardware – partea fizică: componentele materiale ale calculatorului (procesor, memorie, stocare, tastatură, monitor)
  • Software – programele și componentele logice care stabilesc ce operații trebuie realizate

Hardware – componentele unui sistem de calcul

Putem înțelege hardware-ul printr-o analogie cu o bucătărie. Aceasta este o simplificare didactică – procesorul nu "gândește" ca un bucătar și memoria RAM nu funcționează literalmente ca o masă – dar ajută la formarea unei prime imagini mentale.

Procesorul (CPU)

Execută instrucțiuni elementare: transferă date, realizează operații aritmetice, compară valori și decide ce instrucțiune urmează. Un program complex este format, la nivelurile inferioare, din milioane de astfel de operații elementare executate în fracțiuni de secundă. Viteza procesoarelor moderne se măsoară în gigahertz (miliarde de cicluri pe secundă).

Memoria RAM

Spațiul de lucru temporar al programelor în execuție. Când deschizi un document sau rulezi un program, acesta este încărcat din stocare în RAM, de unde procesorul poate accesa datele rapid. La oprirea calculatorului, conținutul RAM se pierde. De aceea, un document nesalvat dispare dacă se întrerupe alimentarea.

Stocarea (SSD / HDD)

Memoria persistentă a sistemului. Datele rămân stocate și după oprire. SSD-urile (Solid State Drive) sunt semnificativ mai rapide decât HDD-urile (Hard Disk Drive) tradiționale, deoarece nu au componente mecanice în mișcare. Diferența de viteză față de RAM este de câteva ordine de mărime.

Intrare și ieșire (I/O)

Dispozitivele de intrare (tastatură, mouse, microfon, senzori) introduc date în sistem. Dispozitivele de ieșire (monitor, difuzoare, imprimantă) prezintă rezultatele. Unele dispozitive sunt mixte: un touchscreen este simultan intrare și ieșire.

De reținut despre RAM vs. stocare

RAM = rapid, temporar, volatile (se pierde la oprire). SSD/HDD = mai lent, persistent (rămâne după oprire). Când deschizi un fișier, el este copiat din stocare în RAM. Când îl salvezi, modificările sunt scrise înapoi în stocare. Dacă nu salvezi și se întrerupe curentul, modificările din RAM (nesalvate) se pierd.

De ce sistem binar?

Suntem obișnuiți să scriem numere folosind zece cifre (0–9) – numărăm în baza 10 (sau sistemul zecimal). Sistemele digitale utilizează în schimb baza 2 (sistemul binar). De ce?

Stări discrete în circuite electronice

Un circuit electronic poate reprezenta cu precizie și robustețe două stări distincte: tensiune prezentă sau absentă, condensator încărcat sau descărcat, magnetizare în sensul A sau B. Acestea sunt stări fizice clare, ușor de diferențiat chiar și în prezența zgomotului electronic.

Prin convenție, reprezentăm aceste două stări prin cifrele 0 și 1. Un sistem care utilizează două cifre este un sistem în baza 2. Orice informație – numere, text, imagini, sunete – poate fi codificată ca secvențe de 0 și 1.

Sistemul zecimal – recapitulare

În baza 10, valoarea unui număr depinde de poziția cifrelor. Fiecare poziție reprezintă o putere a lui 10:

Exemplu zecimal
347 = 3 × 10² + 4 × 10¹ + 7 × 10⁰
 = 3 × 100 + 4 × 10 + 7 × 1
 = 300 + 40 + 7
 = 347

Sistemul binar – baza 2

În baza 2, fiecare poziție reprezintă o putere a lui 2. Cifrele disponibile sunt doar 0 și 1:

Exemplu binar → zecimal
1011₂ = 1 × 2³ + 0 × 2² + 1 × 2¹ + 1 × 2⁰
 = 1 × 8 + 0 × 4 + 1 × 2 + 1 × 1
 = 8 + 0 + 2 + 1
 = 11₁₀
Scopul la acest nivel

Nu trebuie să devii expert în conversii între baze. Scopul este să înțelegi că aceeași valoare poate fi reprezentată în baze diferite. Numărul unsprezece este 11 în baza 10 și 1011 în baza 2 – aceeași cantitate, reprezentări diferite.

Bit și byte

Cei doi termeni fundamentali ai lumii digitale:

  • Un bit (binary digit) este o cifră binară: poate lua valoarea 0 sau 1. Este cea mai mică unitate de informație digitală.
  • Un byte (sau octet) este format din 8 biți grupați împreună. Este unitatea practică de bază pentru măsurarea informației.
1 bit → 2 combinații posibile (0 sau 1)
1 byte = 8 biți → 2⁸ = 256 combinații posibile

Cum reprezentăm textul, imaginile și sunetul?

Un calculator lucrează exclusiv cu numere (reprezentate binar). Cum poate, atunci, să stocheze și să prelucreze texte, imagini și sunete? Prin codificare – stabilim o convenție prin care asociem fiecărui tip de informație o reprezentare numerică.

Reprezentarea textului – ASCII și Unicode

Idea este simplă: asociem fiecărui caracter o valoare numerică. Standardul ASCII (American Standard Code for Information Interchange), stabilit în 1963, definea o astfel de asociere pentru 128 de caractere – litere latine mici și mari, cifre, semne de punctuație și câteva caractere de control.

Litera "A" este stocată ca numărul 65, care la rândul lui este stocat ca secvența de biți 01000001. ASCII utilizează 7 biți per caracter (128 combinații posibile); în practică, pe sisteme moderne care lucrează cu bytes de 8 biți, caracterele ASCII sunt stocate cu un bit 0 în față, ca în exemplele din tabel. Când afișează textul pe ecran, sistemul citește valorile numerice și le transformă înapoi în simboluri vizuale.

ASCII acoperă doar caracterele limbii engleze și nu suportă diacritice sau caractere din alte sisteme de scriere. Sistemele moderne utilizează Unicode, standardul universal de codificare a caracterelor, care definește în versiunea 17.0 (septembrie 2025) un total de 159.801 de caractere din 172 de sisteme de scriere ale lumii, inclusiv emoji. UTF-8 este cea mai răspândită codificare Unicode și este compatibilă cu ASCII: primele 128 de puncte de cod Unicode sunt identice cu ASCII.

De ce textul "123" diferă de numărul 123?

Textul "123" este stocat ca trei bytes: 49 (caracterul '1'), 50 (caracterul '2'), 51 (caracterul '3'). Numărul întreg 123 este stocat complet diferit, ca valoare numerică binară. Aceasta explică de ce în programare există tipuri separate pentru text și pentru numere.

Reprezentarea imaginilor

O imagine digitală este o colecție de pixeli (picture elements) – puncte mici de culoare aranjate într-o grilă. Fiecărui pixel îi sunt asociate valori numerice care descriu culoarea sa. Modelul cel mai frecvent este RGB: trei valori de la 0 la 255, câte una pentru roșu (Red), verde (Green) și albastru (Blue).

Imagine→ Grilă de pixeli→ Valori RGB (0–255)→ Biți

De exemplu, roșu pur este (255, 0, 0): roșu la intensitate maximă, verde și albastru absente. Albul este (255, 255, 255): toate culorile la intensitate maximă. Negrul este (0, 0, 0). O imagine de 1920×1080 pixeli (Full HD) conține 2.073.600 de pixeli, fiecare cu 3 valori de câte 1 byte = aproximativ 6 MB de date înainte de compresie.

Reprezentarea sunetului

Sunetul este, fizic, o undă de presiune ce variază continuu în timp. Sistemele digitale nu pot stoca valori continue – pot stoca numai numere discrete. Procesul de digitizare a sunetului implică eșantionarea: măsurarea amplitudinii undei sonore la intervale regulate de timp și stocarea valorilor numerice rezultate.

Sunet (undă continuă)→ Eșantionare (măsurători periodice)→ Valori numerice→ Biți

Un CD audio utilizează o frecvență de eșantionare de 44.100 de eșantioane pe secundă (44.1 kHz) și 16 biți per eșantion. Calitatea sunetului depinde de frecvența de eșantionare (cu cât mai mare, cu atât mai fidel reproducerea frecvențelor înalte) și de adâncimea de biți (cu cât mai mulți biți, cu atât mai mare gama dinamică).

Mesajul esențial

Informații foarte diferite ca natură – text, imagini, sunete, videoclipuri, date de orice tip – pot fi toate reprezentate numeric. Din acest motiv, același sistem de calcul poate prelucra toate aceste tipuri de informație: dedesubtul oricărei prelucrări se află operații cu numere reprezentate binar.

Software – de la hardware la programe utile

Dacă avem procesor, RAM, SSD, tastatură și monitor – de ce calculatorul nu face automat ceva util? Hardware-ul oferă capacitățile fizice, dar nu știe ce să facă cu ele. Acesta este rolul software-ului.

Software-ul reprezintă programele și componentele logice care stabilesc ce operații trebuie realizate pe hardware. Fără software, un calculator este o colecție de componente electronice fără nicio funcționalitate practică.

Ierarhia unui sistem de calcul

↓ apeluri de sistem (system calls) – aplicațiile cer servicii SO-ului
Sistem de operare – kernel + drivere de dispozitiv

O notă despre simplificare

Diagrama de mai sus este o simplificare didactică utilă. În realitate, un sistem de operare modern are o arhitectură internă mai complexă (kernel, spațiu utilizator, drivere, subsisteme). La acest nivel introductiv, modelul în două straturi – aplicații / sistem de operare / hardware – este suficient pentru a înțelege rolul fiecărei componente.

Sistemul de operare

Sistemul de operare (Windows, Linux, macOS) este software-ul care gestionează resursele hardware și oferă servicii aplicațiilor prin intermediul unor interfețe numite apeluri de sistem (system calls). El rezolvă probleme esențiale: cum rulează mai multe programe „simultan" pe un singur procesor prin comutare rapidă între ele (time-sharing), cum este gestionată memoria RAM pentru a preveni interferența între programe și cum este controlat accesul la dispozitive și fișiere. Fără sistem de operare, fiecare program ar trebui să includă propriul cod pentru a controla direct hardware-ul – o sarcină enormă și imposibil de standardizat.

Driverele de dispozitiv sunt componente ale sistemului de operare (sau strâns legate de el) care știu să comunice cu hardware specific – placa de rețea, placa video, imprimanta. Ele nu sunt un nivel separat între SO și hardware, ci parte din stratul SO.

Firmware – un termen distinct

Firmware-ul (de ex. BIOS/UEFI al unui calculator) este cod stocat permanent în cipuri de pe placa de bază sau în dispozitive hardware. El pornește înainte de sistemul de operare și inițializează hardware-ul la pornire. Nu este un strat software intermediar între SO și hardware – este mai degrabă software-ul „incorporat" în hardware-ul însuși. La nivelul acestui curs, distincția nu este esențială, dar termenul poate apărea în contexte tehnice.

Aplicații

Aplicațiile sunt programele pe care le folosim zilnic: browser, procesor de text, editor de imagini, jocuri. Ele rulează în spațiul utilizator (user space) și nu pot accesa direct hardware-ul – toate cererile de acces la fișiere, rețea sau dispozitive trec prin sistemul de operare. Un browser, de exemplu, nu știe cum funcționează cipul de rețea fizic – transmite o cerere sistemului de operare, care o gestionează prin driverul corespunzător.

Compilatorul – un tip special de software

Un compilator este o aplicație – rulează în spațiul utilizator, la fel ca un browser sau un editor de text. Primește fișiere cu cod sursă și produce un program executabil. Compilatorul C++ (de ex. GCC sau Clang) nu face parte din sistemul de operare – este un program separat, instalat separat, care folosește serviciile SO-ului ca orice altă aplicație.

De la cod sursă la primul program C++

Codul sursă

Programul pe care îl scriem într-un editor se numește cod sursă. Pentru C++, utilizăm fișiere cu extensia .cpp. Codul sursă este text simplu – poate fi deschis cu orice editor de text, dar pentru confort utilizăm editoare specializate sau IDE-uri (Integrated Development Environments) care oferă colorarea sintaxei, completare automată și integrarea compilatorului.

Cele patru etape ale compilării C++

Transformarea codului sursă într-un program executabil nu se face într-un singur pas. Conform documentației GCC, procesul implică patru etape distincte, întotdeauna în aceeași ordine: preprocesare, compilare propriu-zisă, asamblare și link-editare.

Etapă Program Intrare Ieșire Ce face
1. Preprocesare cpp main.cpp main.i Expandează #include (inserează conținutul header-elor), #define (înlocuiește macro-urile) și procesează compilarea condițională. Rezultatul este cod C++ pur, fără directive.
2. Compilare propriu-zisă cc1plus main.i main.s Analizează sintaxa și semantica codului C++, detectează erori, optimizează și traduce în cod Assembly – o reprezentare simbolică, încă lizibilă de om, a instrucțiunilor procesorului. Nu produce binar.
3. Asamblare as main.s main.o Convertește codul Assembly în cod mașinii binar, producând un fișier obiect (.o). Conține instrucțiuni binare, dar referințele către funcții din alte fișiere sau biblioteci rămân nerezolvate.
4. Link-editare ld main.o + biblioteci executabil Combină toate fișierele obiect și bibliotecile necesare, rezolvă toate referințele și produce executabilul final – fișier binar complet, specific sistemului de operare și arhitecturii.
Pipeline de compilare
main.cpp ──[preprocesor]── main.i (cod C++ pur, fără directive)
main.i ──[compilator]─── main.s (cod Assembly)
main.s ──[asamblor]───── main.o (cod mașinii binar – fișier obiect)
main.o ──[link-editor]── program (executabil final)
De ce spunem „compilăm" când sunt patru pași?

În practică, utilitarul g++ orchestrează automat toate patru etapele cu o singură comandă: g++ main.cpp -o program. Fișierele intermediare (.i, .s, .o) sunt create și șterse automat. Putem opri procesul după orice etapă: -E după preprocesare, -S după compilare, -c după asamblare.

Compilatorul nu produce direct cod binar

O concepție greșită frecventă: „compilatorul traduce codul C++ direct în 0 și 1." Corect: compilatorul propriu-zis produce cod Assembly, nu binar. Binar produce asamblorul – un program separat. Aceasta este o distincție importantă atunci când înveți să citești mesaje de eroare sau să înțelegi cum funcționează optimizările.

Cum execută procesorul codul binar

Odată ce executabilul este produs și sistemul de operare îl încarcă în RAM, procesorul preia controlul. El nu „înțelege" programul ca un întreg – execută instrucțiunile una câte una, repetând continuu un ciclu de trei pași numit Fetch–Decode–Execute (Preia–Decodifică–Execută). Frecvența de ceas a procesorului (măsurată în GHz) indică câte miliarde de astfel de cicluri au loc pe secundă.

Componentele implicate în execuție

ComponentăRol
Program Counter (PC) Registru special care conține adresa de memorie a următoarei instrucțiuni de executat. Este incrementat automat după fiecare instrucțiune fetched. Dacă o instrucțiune de salt (JUMP) este executată, PC este modificat la adresa de destinație.
Instruction Register (IR) Registru care conține instrucțiunea curentă preluată din memorie, în așteptarea decodificării de către Unitatea de Control.
Unitatea de Control (CU) Orchestrează întregul ciclu. Decodifică instrucțiunea din IR, extrage opcode-ul și operanzii, și trimite semnale de control celorlalte componente (ALU, regiștri, sistem de memorie).
ALU (Arithmetic Logic Unit) Efectuează operațiile aritmetice (adunare, scădere, înmulțire) și logice (AND, OR, NOT, comparații). Primește operanzii din regiștri și scrie rezultatul înapoi într-un registru.
Regiștri generali Locații de stocare extrem de rapide, situate direct în procesor. ALU operează numai pe date aflate în regiștri; datele din RAM trebuie mai întâi încărcate într-un registru înainte de a putea fi procesate.

Ciclul Fetch–Decode–Execute în detaliu

PasCe se întâmplăComponente
1. Fetch
Preluare		 PC furnizează adresa instrucțiunii următoare. Procesorul trimite această adresă prin magistrala de adrese către RAM (sau cache L1, dacă instrucțiunea este deja acolo). Instrucțiunea binară este returnată prin magistrala de date și plasată în Instruction Register. PC este incrementat. PC, IR, magistrale de adrese și date, RAM/cache
2. Decode
Decodificare		 Unitatea de Control analizează pattern-ul binar din IR. Extrage opcode-ul (codul operației: ADD, LOAD, JUMP etc.) și operanzii (registrele sau adresele de memorie implicate). Generează semnalele de control care pregătesc ALU și regiștrii pentru execuție. Unitatea de Control, decodificator de instrucțiuni
3. Execute
Execuție		 Instrucțiunea este efectuată conform tipului ei:
• Aritmetică/logică: ALU efectuează operația pe operanzii din regiștri și scrie rezultatul.
• Transfer de date: date sunt mutate între regiștri și RAM (instrucțiuni LOAD/STORE).
• Salt: PC este modificat pentru a schimba fluxul execuției (ex: pentru if, for).		 ALU, regiștri, sistem de memorie
Exemplu – de la C++ la instrucțiune binară
// Cod C++ (nivel înalt):
int rezultat = a + b;

// Cod Assembly generat de compilator (simplificat, x86-64):
MOV EAX, [a] // LOAD: încarcă valoarea lui a în registrul EAX
ADD EAX, [b] // ARITMETIC: adaugă b la EAX; rezultatul rămâne în EAX
MOV [rezultat], EAX // STORE: salvează EAX în locația de memorie a lui rezultat // Instrucțiunea ADD tradusă în binar de asamblor (exemplu simplificat):
// opcode operanzi
// 00000011 11000011
// ^^^^^^^^^ ADD între doi regiștri conform ISA x86
Firul complet: de la C++ la execuție hardware

int rezultat = a + b; este cod C++ pe care îl scriem noi. Compilatorul îl traduce în Assembly (ADD EAX, EBX). Asamblorul convertește Assembly-ul în binar (00000011 11000011). Link-editorul produce executabilul. Sistemul de operare îl încarcă în RAM. PC indică prima instrucțiune. Ciclul Fetch–Decode–Execute se repetă instrucțiune cu instrucțiune, de miliarde de ori pe secundă, până la return 0.

Primul program C++

Primul program C++

C++ – Hello World
#include <iostream>
using namespace std;

int main() {
 cout << "Hello World!";
 return 0;
}

Rezultatul rulării: Hello World!

Ce face fiecare linie?

#include <iostream>
Include biblioteca standard de intrare/ieșire. Fără această linie, compilatorul nu știe ce înseamnă cout. iostream = input/output stream.
using namespace std;
Permite utilizarea numelor din spațiul de nume standard (std) fără a le califica complet. Fără această linie, ar trebui să scriem std::cout în loc de cout.
int main() {
Definește funcția principală – punctul de intrare al programului. Orice program C++ trebuie să conțină exact o funcție main(). int indică că funcția returnează un număr întreg.
cout << "Hello World!";
cout (character output) este fluxul de ieșire standard – trimite text pe ecran. << este operatorul de inserție. Textul afișat trebuie scris între ghilimele duble. Instrucțiunea se termină obligatoriu cu ;.
return 0;
Funcția main() returnează un cod de stare sistemului de operare. Valoarea 0 indică prin convenție că programul s-a terminat cu succes (fără erori). Orice altă valoare semnalează o eroare.
}
Închide blocul funcției main(). Fiecare acoladă deschisă { trebuie să aibă o acoladă de închidere pereche }.
C++ este case-sensitive

cout, Cout și COUT sunt trei lucruri complet diferite. Numai cout (cu litere mici) este recunoscut de compilator. Această sensibilitate la majuscule/minuscule se aplică tuturor cuvintelor din C++.

Prima eroare intenționată

Un pas esențial în învățarea programării este să înțelegi că erorile de compilare sunt informații, nu eșecuri. Compilatorul este un instrument precis care îți spune exact ce nu respectă regulile limbajului.

Încearcă să elimini punct-virgula de la finalul instrucțiunii cout:

C++ – Cu eroare deliberată
#include <iostream>
using namespace std;

int main() {
 cout << "Hello World!" // <-- lipsește ; la finalul liniei return 0;
}

Compilatorul va produce un mesaj de eroare similar cu:

Mesaj de eroare
error: expected ';' before 'return'

Compilatorul nu ne spune că am greșit ceva vag – ne spune exact ce lipsește și unde. Aceasta este o capacitate de diagnosticare valoroasă. Reintroduci ; și recompilezi: eroarea dispare, programul funcționează.

Mesajul esențial despre erori

O eroare de compilare este o informație despre program, nu un eșec personal al programatorului. Fiecare programator, indiferent de experiență, întâmpină erori de compilare zilnic. Diferența față de un începător este că un programator experimentat știe să citească mesajele de eroare și să le corecteze rapid.

Întrebări de verificare

Acestea sunt întrebări scurte, fără presiunea unui test formal. Scopul este să verifici dacă ai înțeles ideile esențiale ale sesiunii.

1. Care este diferența dintre hardware și software?

Hardware este partea fizică a calculatorului – componentele materiale pe care le poți atinge: procesor, RAM, SSD, tastatură, monitor. Software sunt programele și componentele logice care stabilesc ce operații trebuie realizate: sisteme de operare, aplicații, compilatoare. Hardware-ul oferă capacitățile fizice; software-ul le folosește pentru a realiza sarcini utile.

2. Care este rolul general al procesorului?

Procesorul (CPU) execută instrucțiunile programului. El poate transfera date între componente, realiza calcule aritmetice și logice, compara valori și decide ce instrucțiune urmează să fie executată. Un program complex este format, la nivelurile inferioare, din milioane de astfel de operații elementare.

3. De ce este utilă memoria RAM?

RAM este spațiul de lucru temporar al programelor în execuție. Procesorul accesează datele din RAM mult mai rapid decât din stocare (SSD/HDD). Fără suficientă RAM, programele nu pot încărca datele necesare și funcționarea calculatorului devine lentă. RAM este volatilă – conținutul se pierde la oprirea calculatorului.

4. Care este diferența dintre RAM și SSD?

RAM: rapidă, temporară (conținutul se pierde la oprire), utilizată pentru datele programelor în execuție. SSD/HDD: mai lentă decât RAM, persistentă (conținutul rămâne după oprire), utilizată pentru stocarea permanentă a fișierelor și programelor. Când deschizi un program, el este copiat din SSD în RAM pentru a fi executat.

5. Ce este un bit? Câți biți are un byte?

Un bit (binary digit) este cea mai mică unitate de informație digitală și poate lua valoarea 0 sau 1. Un byte (octet) este format din 8 biți. Cu 8 biți se pot reprezenta 2⁸ = 256 combinații distincte.

6. De ce poate o literă fi reprezentată numeric?

Prin codificare – o convenție care asociază fiecărui caracter o valoare numerică. Standardul ASCII asociază, de exemplu, literei 'A' valoarea numerică 65, iar valoarea 65 este stocată în binar ca 01000001. Sistemul nu "înțelege" că 01000001 reprezintă o literă – știe doar că trebuie să afișeze simbolul vizual asociat acestei valori prin convenție.

7. Ce este un algoritm?

O succesiune finită și bine precizată de pași, utilizată pentru rezolvarea unei probleme. Caracteristici esențiale: are un număr determinat de pași (finit), fiecare pas este clar și neambiguu (bine precizat), pornește de la date de intrare și produce un rezultat determinat.

8. Ce este un limbaj de programare?

Un limbaj formal cu reguli precise de sintaxă și semantică, utilizat pentru exprimarea programelor destinate execuției pe un sistem de calcul. Este intermediarul care permite programatorului să exprime instrucțiuni într-o formă suficient de apropiată de limbajul uman pentru a fi scrisă, dar suficient de precisă pentru a fi tradusă în instrucțiuni de procesor.

9. De ce avem nevoie de un compilator?

Procesorul poate executa numai instrucțiuni în cod mașinii (secvențe binare). Codul sursă C++ este scris în formă lizibilă pentru oameni și nu poate fi executat direct de procesor. Compilatorul traduce codul sursă în instrucțiuni binare pe care procesorul le înțelege, verificând în același timp că codul respectă regulile sintactice ale limbajului.

10. Care este diferența dintre cod sursă și program executabil?

Codul sursă este textul scris de programator în limbajul de programare (fișier .cpp) – lizibil de oameni, nu executabil direct de procesor. Programul executabil este fișierul binar produs de compilator, conținând instrucțiuni în cod mașinii specifice sistemului de operare și arhitecturii – poate fi rulat direct pe sistem, dar nu este lizibil de oameni.

11. Ce este sistemul de operare și de ce este necesar?

Sistemul de operare (Windows, Linux, macOS) este software-ul care gestionează resursele hardware și oferă servicii aplicațiilor. Este necesar pentru că fără el fiecare program ar trebui să includă propriul cod pentru a controla direct hardware-ul – o sarcină enormă și imposibil de standardizat. Sistemul de operare abstractizează hardware-ul și oferă un set uniform de servicii tuturor aplicațiilor.

12. Ce face instrucțiunea cout << "text"; în C++?

cout (character output) este fluxul de ieșire standard – trimite date pe ecran. Operatorul << (operator de inserție) transmite datele din dreapta sa către fluxul din stânga. "text" este un șir de caractere literal. Instrucțiunea în ansamblu afișează textul pe ecran. ; marchează sfârșitul instrucțiunii – obligatoriu în C++.

Rezumat – De reținut

Ideile esențiale ale sesiunii 1
  1. Un algoritm este o succesiune finită și precisă de pași pentru rezolvarea unei probleme. Calculatorul are nevoie de instrucțiuni exacte, fără ambiguitate.
  2. Hardware = componente fizice (CPU, RAM, SSD, I/O). Software = programe și componente logice.
  3. Procesorul execută instrucțiuni elementare; RAM este memoria temporară de lucru; SSD/HDD este stocarea persistentă.
  4. Sistemele digitale utilizează reprezentare binară (0 și 1) deoarece circuitele electronice pot reprezenta robust două stări distincte.
  5. Un bit = 0 sau 1. Un byte = 8 biți = 256 combinații posibile.
  6. Text, imagini și sunete pot fi toate reprezentate numeric și stocate ca secvențe de biți.
  7. Structura unui sistem: Aplicații → Sistem de operare → Hardware.
  8. Fluxul de creare a unui program: Problemă → Algoritm → Cod sursă → Compilare → Executabil → Execuție → Rezultat.
  9. O eroare de compilare este o informație despre program, nu un eșec personal.

Schimb de valoare între variabile

Cerință

Declară două variabile întregi a = 10 și b = 25. Afișează valorile inițiale. Apoi schimbă valorile între ele (după operație, a trebuie să aibă 25 și b să aibă 10) și afișează valorile finale.

Output așteptat
Inainte: a = 10, b = 25
Dupa : a = 25, b = 10
Indiciu

Nu poți face pur și simplu a = b; b = a; – după prima atribuire, a are deja valoarea lui b, deci ai pierdut valoarea originală a lui a. Ai nevoie de o variabilă temporară: int temp = a; înainte de a suprascrie a.

Soluție
C++
#include <iostream>
using namespace std;

int main() {
 int a = 10;
 int b = 25;

 cout << "Inainte: a = " << a << ", b = " << b << endl;

 // Schimbul necesită o variabilă temporară int temp = a; // temp = 10 a = b; // a = 25 b = temp; // b = 10 cout << "Dupa : a = " << a << ", b = " << b << endl;
 return 0;
}

De reținut: Acesta este un algoritm clasic de schimb de valori. Variabila temporară este necesară deoarece o atribuire suprascrie valoarea anterioară – nu o mută, o înlocuiește definitiv. Această tehnică apare frecvent în algoritmii de sortare.

Ce ai practicat în aceste exerciții

Structura de bază a unui program C++ (#include, main(), return 0). Afișarea de text fix și de valori ale variabilelor cu cout <<. Declararea variabilelor de tip int și string. Calculul unei expresii aritmetice și stocarea rezultatului într-o variabilă nouă. Variabila temporară ca instrument de bază în algoritmică. Toate acestea vor fi aprofundate formal în Sesiunea 2.
