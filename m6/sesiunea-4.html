Instrucțiunea

Într-un program, prelucrarea datelor se realizează printr-o succesiune de acțiuni. Aceste acțiuni sunt descrise cu ajutorul instrucțiunilor.

Definiție

O instrucțiune este o construcție a limbajului de programare care descrie o acțiune ce trebuie executată în cadrul programului.

De exemplu, x = 10; este o instrucțiune care atribuie valoarea 10 variabilei x, iar cout << x << endl; este o instrucțiune prin care este afișată valoarea variabilei x. Instrucțiunile sunt, așadar, elementele prin care sunt descrise acțiunile efective ale programului.

Să analizăm un program complet:

C++
#include <iostream>
using namespace std;

int main() {
    int a = 5;
    int b = 3;
    int suma = a + b;

    cout << suma << endl;

    return 0;
}

În acest program sunt executate mai multe acțiuni: sunt declarate și inițializate variabilele a și b; este calculată expresia a + b; rezultatul este atribuit variabilei suma; valoarea variabilei suma este afișată; execuția funcției main este încheiată. Instrucțiunile transformă astfel descrierea unei probleme într-o succesiune de acțiuni executabile de calculator.

Expresii și instrucțiuni

O expresie și o instrucțiune nu sunt același lucru. Expresia este evaluată și produce o valoare, în timp ce instrucțiunea descrie o acțiune care trebuie executată de program. În C++, anumite instrucțiuni pot conține una sau mai multe expresii.

ExpresieInstrucțiune
Exemplua + bsuma = a + b;
Ce se întâmplăevaluare → valoareexecuție → acțiune

În C++ există și instrucțiuni expresie — forma generală este expresie;. De exemplu, x = 10; sau x++; sunt instrucțiuni expresie: evaluarea expresiei produce efectul asociat acesteia, iar apoi fluxul de execuție continuă cu instrucțiunea următoare.

Atenție

Nu orice expresie produce un efect util atunci când este scrisă singură ca instrucțiune. De exemplu, a + b; este acceptată sintactic ca instrucțiune expresie, dar valoarea calculată nu este memorată și nu este utilizată.

Clasificarea instrucțiunilor

Instrucțiunile pot fi grupate în funcție de modul în care influențează desfășurarea execuției programului. Le organizăm în patru categorii principale:

Secvențiale

Păstrează ordinea normală de execuție — controlul trece la instrucțiunea următoare.

  • declarație
  • instrucțiune expresie
  • instrucțiune compusă

De selecție

Permit alegerea uneia sau mai multor căi de execuție posibile, în funcție de o condiție.

  • if
  • if–else
  • switch

De ciclare

Numite și repetitive sau iterative — repetă o secvență de cod de mai multe ori.

  • while
  • do–while
  • for

De salt

Transferă în mod explicit controlul într-un alt punct al programului sau întrerup execuția.

  • break
  • continue
  • return
  • goto
Punct cheie

Instrucțiunile secvențiale păstrează ordinea normală de execuție, în timp ce instrucțiunile de selecție, de ciclare și de salt pot modifica această ordine.

Instrucțiunea if introduce o instrucțiune-corp în fluxul de execuție numai dacă expresia condițională este adevărată: if (nota >= 5) cout << "Promovat" << endl;. Instrucțiunea if–else permite alegerea uneia dintre două instrucțiuni-corp, iar switch permite selectarea unei alternative în funcție de valoarea unei expresii-selector. Aceste trei instrucțiuni sunt studiate în detaliu în secțiunea despre structura alternativă.

Instrucțiunile de ciclare folosesc toate o condiție pentru a decide continuarea sau încheierea repetării — de exemplu, while (i < 5) { cout << i << endl; i++; } execută blocul repetat cât timp i < 5 este adevărată. Nu le dezvoltăm aici; ele vor fi studiate separat.

Instrucțiunile de salt modifică explicit fluxul: break; iese imediat dintr-o instrucțiune de ciclare sau dintr-un switch; continue; încheie iterația curentă și trece la următoarea; return; (sau return expresie;) încheie execuția funcției curente; goto eticheta; transferă controlul către o instrucțiune etichetată din aceeași funcție.

Atenție la goto

goto există în C++, dar utilizarea salturilor necondiționate poate reduce claritatea programului. Acolo unde este posibil, sunt preferate mecanisme precum break, continue sau return.

Instrucțiuni simple și instrucțiuni compuse

Din punctul de vedere al organizării lor, distingem între instrucțiuni simple și instrucțiuni compuse. Această diferențiere este importantă deoarece multe instrucțiuni ale limbajului, precum cele de selecție sau de ciclare, au drept corp o instrucțiune — iar acel corp poate fi o instrucțiune simplă sau una compusă.

Instrucțiunea simplă

O instrucțiune simplă nu este formată dintr-un bloc de mai multe instrucțiuni delimitat prin acolade. De exemplu, x = 10; și cout << x << endl; sunt instrucțiuni simple. Într-o instrucțiune de selecție ca if (x > 0) cout << "Pozitiv" << endl;, corpul lui if este tot o instrucțiune simplă.

În majoritatea cazurilor, instrucțiunile simple se termină cu ; — terminatorul instrucțiunii, care face parte din instrucțiunea respectivă. Există și o instrucțiune specială, formată numai din ;, numită instrucțiune nulă: nu execută nicio acțiune propriu-zisă, dar este sintactic validă.

Instrucțiunea compusă

O instrucțiune compusă este formată din zero, una sau mai multe instrucțiuni cuprinse între o pereche de acolade:

Formă generală
{
    instructiune1;
    instructiune2;
    ...
    instructiuneN;
}

Acoladele fac parte din instrucțiunea compusă și nu trebuie urmate de punct și virgulă — adăugarea unui ; după acolada de închidere introduce în plus o instrucțiune nulă.

Relația dintre instrucțiunea compusă și bloc

Instrucțiunea compusă formează un bloc. În C++, cei doi termeni sunt strâns legați: instrucțiune compusă ↔ bloc. Un bloc grupează una sau mai multe instrucțiuni într-o unitate care poate fi folosită acolo unde sintaxa cere o singură instrucțiune.

Blocurile de instrucțiuni

Un bloc de instrucțiuni este o grupare de zero, una sau mai multe instrucțiuni care sunt tratate împreună. În C++, un bloc este realizat printr-o instrucțiune compusă, delimitată prin acolade { }.

Blocurile sunt importante deoarece permit utilizarea mai multor instrucțiuni acolo unde construcția limbajului așteaptă o singură instrucțiune:

C++
if (x > 0) {
    cout << "Numar pozitiv" << endl;
    cout << "Valoarea este " << x << endl;
}

Din punct de vedere sintactic, instrucțiunea if are un singur corp, dar acel corp este o instrucțiune compusă formată din două instrucțiuni. Aceasta este utilitatea fundamentală a blocului.

Blocuri vide, cu o instrucțiune, cu mai multe instrucțiuni

Un bloc poate să nu conțină nicio instrucțiune — { } este un bloc valid, deși nu apare des în programele introductive. Acoladele definesc blocul chiar și atunci când între ele nu apare nicio instrucțiune. Un bloc poate conține și o singură instrucțiune, sau mai multe — utilitatea principală a blocurilor apare tocmai atunci când mai multe instrucțiuni trebuie tratate împreună, de exemplu în corpul unui if.

Notă

Utilizarea unui bloc chiar și pentru o singură instrucțiune poate contribui la un stil de scriere unitar și poate face mai vizibilă structura programului.

Blocuri imbricate și domeniul de vizibilitate

Un bloc poate conține în interior un alt bloc — această organizare se numește imbricare:

C++
{
    int x = 10;
    {
        int y = 20;
        cout << x + y << endl;
    }
    cout << x << endl;
}

Blocurile nu au doar rolul de a grupa instrucțiuni: ele delimitează și un domeniu de vizibilitate pentru variabilele declarate în interiorul lor. O variabilă declarată într-un bloc este vizibilă în acel bloc după punctul declarării și nu mai poate fi utilizată în afara lui. În blocurile imbricate, blocul interior poate utiliza variabile declarate în blocul exterior.

Blocuri în C++, Java și Python

Deși sintaxa diferă, ideea de bază este aceeași: mai multe instrucțiuni pot fi grupate astfel încât să fie tratate împreună. C++ și Java delimitează blocurile prin acolade { }. Python nu folosește acolade — apartenența instrucțiunilor la același bloc este indicată prin indentare:

Python
if x > 0:
    print("Numar pozitiv")
    print(x)

print("Programul continua")

Primele două instrucțiuni print aparțin blocului lui if, deoarece au același nivel de indentare; ultima instrucțiune, la un nivel diferit, se află în afara blocului.

Fluxul de execuție

Prin flux de execuție înțelegem ordinea în care sunt executate instrucțiunile unui program. În forma cea mai simplă, fluxul urmează ordinea instrucțiunilor din textul sursă — instrucțiunile sunt executate secvențial, de sus în jos:

Reprezentarea algoritmilor: scheme logice și pseudocod

Atunci când proiectăm un program, nu trecem întotdeauna direct la scrierea codului sursă. Este util să folosim forme intermediare de reprezentare, care descriu pașii algoritmului și modul în care se deplasează controlul execuției — două astfel de instrumente sunt schemele logice și pseudocodul.

Schemele logice

O schemă logică este o reprezentare grafică a unui algoritm: pașii sunt reprezentați prin simboluri grafice standardizate, iar ordinea execuției este indicată prin săgeți.

Pseudocodul

Pseudocodul este o descriere textuală, structurată și aproape algoritmică a pașilor unei rezolvări. Nu aparține unui anumit limbaj de programare și nu respectă reguli sintactice rigide, dar trebuie să fie clar, ordonat și ușor de transformat în cod. Avantajele sale: este mai ușor de scris decât o schemă logică, este mai apropiat de limbajul natural, evidențiază clar pașii algoritmului și poate fi transformat relativ ușor în cod C++.

Pseudocodul descrie textual pașii algoritmului, schema logică evidențiază vizual fluxul de execuție, iar codul C++ reprezintă implementarea concretă — cele trei forme descriu același algoritm la niveluri diferite de reprezentare.

Structurile de control

Am privit până acum execuția unui program din două perspective complementare. Prima este cea a limbajului de programare — la acest nivel analizăm instrucțiunile pe care C++ ni le pune la dispoziție (secvențiale, de selecție, de ciclare, de salt). A doua este cea a organizării fluxului de execuție — la acest nivel discutăm despre structurile fundamentale prin care este organizată execuția unui algoritm.

Definiție

O structură de control reprezintă o modalitate de organizare a execuției instrucțiunilor unui program: stabilește modul în care se deplasează controlul execuției de la o instrucțiune la alta.

Cele două perspective sunt legate, dar nu trebuie confundate: if este o instrucțiune de selecție a limbajului C++, iar prin utilizarea ei putem implementa o structură alternativă. La fel, while și for sunt instrucțiuni iterative prin care implementăm o structură repetitivă.

Punct cheie

Instrucțiunea este construcția concretă a limbajului. Structura de control este modelul după care este organizat fluxul execuției.

La nivel conceptual, organizarea fluxului de execuție poate fi descrisă prin trei structuri fundamentale:

Alternativă (de selecție)Alegerea unei ramuri de execuție în funcție de o condițieif, if–else, switch
Repetitivă (iterativă)Repetarea unei instrucțiuni sau a unui bloc de mai multe oriwhile, do–while, for

Fiecare categorie de instrucțiuni realizează concret o anumită structură de control:

În programele reale, structurile de control sunt rareori utilizate izolat — pot fi combinate pentru a descrie comportamente mai complexe. De exemplu, o structură repetitivă poate conține o structură alternativă:

C++
for (int i = 0; i < 10; i++) {
    if (i % 2 == 0) {
        cout << i << endl;
    }
}

Instrucțiunile de salt (break, continue, return, goto) nu reprezintă, în această clasificare, o structură fundamentală separată, dar pot modifica direct fluxul normal de execuție.

Imbricarea structurilor de control

Atunci când o structură de control apare în interiorul alteia, spunem că structurile sunt imbricate. Am întâlnit deja acest concept la nivelul blocurilor; el se aplică în același mod și structurilor de control.

C++ – două structuri alternative imbricate
if (x > 0) {
    if (x < 10) {
        cout << "x este intre 1 si 9" << endl;
    }
}

Prima structură verifică x > 0; numai dacă această condiție este adevărată se ajunge la a doua, care verifică x < 10. Structurile repetitive pot fi și ele imbricate, iar imbricarea poate combina și tipuri diferite de structuri — de exemplu o structură alternativă inclusă într-o structură repetitivă:

C++ – ilustrativ (ciclarea va fi studiată separat)
while (x > 0) {
    if (x % 2 == 0) {
        cout << x << endl;
    }
    x--;
}

Structura alternativă: luarea deciziilor

O decizie apare atunci când execuția programului depinde de rezultatul unei verificări. De exemplu, vrem să afișăm mesajul Promovat numai dacă nota este cel puțin 5 — conceptual, avem întrebarea „Este nota >= 5?", iar în funcție de răspuns programul continuă pe o anumită ramură.

O condiție este o expresie utilizată pentru a decide dacă o anumită ramură de execuție trebuie urmată — de exemplu, nota >= 5. Condițiile folosesc operatorii relaționali (== != < > <= >=) și pot fi combinate cu operatori logici (&& || !), studiați deja în sesiunea anterioară. Rezultatul unei condiții este interpretat logic ca true sau false; pentru if, o valoare egală cu zero este interpretată ca fals, iar o valoare nenulă permite executarea instrucțiunii-corp.

    instructiune2;
}

    cout << "Persoana este majora." << endl;

Instrucțiunea if implementează o selecție simplă: corpul îi este permis să intre în fluxul execuției numai dacă este îndeplinită condiția. Execuția are două posibilități: condiția e adevărată și corpul este executat, sau condiția e falsă și corpul este omis.

Structura alternativă dublă — if–else

Structura alternativă dublă permite alegerea uneia dintre două posibilități, realizată prin if–else:

Formă generală
if (conditie) {
    instructiuni_DA;
} else {
    instructiuni_NU;
}
C++
if (nota >= 5) {
    cout << "Promovat" << endl;
} else {
    cout << "Nepromovat" << endl;
}

Dacă expresia condițională este adevărată, este executată prima ramură; dacă este falsă, este executată ramura asociată lui else. La o anumită execuție este selectată una și numai una dintre cele două ramuri — ele reprezintă posibilități mutual exclusive.

Selecția multiplă — else if în cascadă și switch

Uneori trebuie să alegem între mai mult de două posibilități. O modalitate este o succesiune de instrucțiuni if–else, cunoscută frecvent ca else-if în cascadă:

C++
if (nota >= 9) {
    cout << "Foarte bine" << endl;
} else if (nota >= 7) {
    cout << "Bine" << endl;
} else if (nota >= 5) {
    cout << "Suficient" << endl;
} else {
    cout << "Nepromovat" << endl;
}

Condițiile sunt verificate în ordine. La întâlnirea primei condiții adevărate, este executată ramura corespunzătoare, iar restul lanțului este ignorat.

O altă instrucțiune de selecție disponibilă în C++ este switch, care selectează o ramură în funcție de valoarea unei expresii-selector:

C++
switch (optiune) {
    case 1:
        cout << "Optiunea 1" << endl;
        break;
    case 2:
        cout << "Optiunea 2" << endl;
        break;
    default:
        cout << "Alta optiune" << endl;
}
Notă

În această sesiune, accentul principal rămâne pe if și if–else; switch este introdus ca mecanism de selecție multiplă. break apare aici doar ca parte a sintaxei uzuale a lui switch — instrucțiunile de salt vor fi studiate separat.

Structuri alternative imbricate

O instrucțiune de selecție poate apărea în corpul altei instrucțiuni de selecție — avem astfel o imbricare, particularizată aici pentru structura alternativă:

C++
if (varsta >= 18) {
    if (arePermis) {
        cout << "Poate conduce." << endl;
    }
}

Mai întâi este evaluată varsta >= 18; numai dacă aceasta este adevărată se ajunge la evaluarea lui arePermis. Structurile alternative imbricate permit exprimarea unor decizii dependente unele de altele, și pot apărea și cu else pe fiecare nivel:

C++
if (a > 0) {
    if (b > 0) {
        cout << "Ambele sunt pozitive." << endl;
    } else {
        cout << "Doar a este pozitiv." << endl;
    }
}
Atenție la if-uri imbricate fără acolade

Atunci când lipsesc acoladele, asocierea unui else cu if-ul corect poate deveni greu de urmărit — regula limbajului este că else se asociază întotdeauna cu cel mai apropiat if anterior care nu are deja un else. Folosirea acoladelor crește lizibilitatea și elimină orice ambiguitate.

Erori frecvente

Eroarea 1 – Punct și virgulă rătăcit după if
C++ – Greșit

}
C++ – Corect

    cout << "Pozitiv";
}

Explicație: punctul și virgula de după if (x > 0) formează o instrucțiune nulă, care devine corpul lui if. Blocul de mai jos nu mai aparține instrucțiunii if — se execută întotdeauna, indiferent de condiție.

Eroarea 2 – Lipsa acoladelor la mai multe instrucțiuni
C++ – Greșit
if (nota >= 5)
    cout << "Promovat";
    cout << "Felicitari"; // se executa MEREU, nu doar cand e promovat
C++ – Corect
if (nota >= 5) {
    cout << "Promovat";
    cout << "Felicitari";
}

Explicație: fără acolade, corpul lui if este format dintr-o singură instrucțiune — doar prima linie. A doua linie, indiferent de indentare, este o instrucțiune separată care se execută necondiționat.

Eroarea 3 – Ordinea greșită într-un else if în cascadă
C++ – Greșit
if (nota >= 5) {
    cout << "Promovat";
} else if (nota >= 9) {
    cout << "Foarte bine"; // nu se va afisa niciodata!
}
C++ – Corect
if (nota >= 9) {
    cout << "Foarte bine";
} else if (nota >= 5) {
    cout << "Promovat";
}

Explicație: pentru o notă de 9 sau 10, prima condiție (nota >= 5) este deja adevărată, deci ramura else if nu mai este evaluată niciodată. Într-o cascadă de condiții care se suprapun, condițiile mai restrictive trebuie testate primele.

Eroarea 4 – Cu ce if se asociază un else?
C++ – Ambiguu la citire
if (a > 0)
    if (b > 0)
        cout << "A";
    else
        cout << "B";
C++ – Clarificat cu acolade
if (a > 0) {
    if (b > 0) {
        cout << "A";
    } else {
        cout << "B";
    }
}

Explicație: else se asociază întotdeauna cu cel mai apropiat if anterior care nu are deja un else — aici, cu if (b > 0), nu cu if (a > 0). Indentarea din exemplul ambiguu sugerează vizual altă asociere decât cea reală — motiv suplimentar pentru a folosi mereu acolade la if-uri imbricate.

C++ – Greșit
// dorim sa verificam: 1 < x < 5
if (1 < x < 5) {
    cout << "Apartine";
}
C++ – Corect
if (x > 1 && x < 5) {
    cout << "Apartine";
}

Explicație: 1 < x < 5 compilează, dar nu face ce pare — se evaluează întâi 1 < x, obținând un bool (0 sau 1), care este apoi comparat numeric cu 5; rezultatul este aproape întotdeauna true, indiferent de x. C++

        cout << "Doar a este pozitiv";
    }
}

Exercițiul 6 — o variabilă auxiliară „aproape" folosită
C++

int b = 5;
int aux = 1;

if (a < b) {
    aux = a;
}

b = aux;

Exercițiul 7 — selecție dublă urmată de un calcul

} else {
    a++;
}

cout << a << " " << b;

Exercițiul 9 — selecție imbricată cu caractere
C++

int b = 12;

Reguli-cheie de reținut

  • Corpul unui if fără acolade este o singură instrucțiune — pentru mai multe instrucțiuni, sunt obligatorii acoladele.
  • Un ; imediat după if (conditie) formează o instrucțiune nulă, care devine corpul lui if — o eroare frecventă și greu de observat vizual.
  • Într-un lanț if / else if, se execută o singură ramură — prima a cărei condiție este adevărată. Ordinea condițiilor contează atunci când ele se suprapun.
  • else se asociază întotdeauna cu cel mai apropiat if anterior fără else — folosește acolade la if-uri imbricate pentru claritate.
  • Blocurile ({ }) grupează instrucțiuni și delimitează domeniul de vizibilitate al variabilelor declarate în interior.
  • O instrucțiune compusă (bloc) nu se termină cu ; după acolada de închidere.
  • 1 < x < 5 nu verifică un interval în C++ — scrie x > 1 && x < 5.
  • Python nu folosește acolade pentru blocuri — indentarea este parte din sintaxă, nu doar estetică.

Întrebări deschise

1. Care este diferența dintre o expresie și o instrucțiune?

O expresie este evaluată și produce o valoare (ex: a + b). O instrucțiune descrie o acțiune care trebuie executată de program (ex: suma = a + b;). Multe instrucțiuni conțin expresii, dar cele două concepte rămân distincte.

2. Ce este o instrucțiune compusă și ce legătură are cu noțiunea de bloc?

O instrucțiune compusă este formată din zero, una sau mai multe instrucțiuni cuprinse între acolade. În C++, un bloc este o instrucțiune compusă — cei doi termeni sunt strâns legați și practic interschimbabili.

3. De ce contează dacă un bloc conține „zero" instrucțiuni? Dați un exemplu.

{ } este un bloc valid, sintactic corect, chiar dacă nu execută nicio acțiune — acoladele definesc blocul indiferent dacă acesta este vid sau nu.

4. Ce se întâmplă dacă adaugi un punct și virgulă imediat după acolada de închidere a unui bloc, de exemplu { x = x + 1; };?

Se introduce, în plus față de bloc, o instrucțiune nulă (formată doar din ;). Aceasta nu produce o eroare de compilare, dar este o instrucțiune suplimentară, de regulă nedorită.

5. Ce este fluxul de execuție și cum se comportă în absența oricărei instrucțiuni de control?

Fluxul de execuție este ordinea în care sunt executate instrucțiunile unui program. În absența unei instrucțiuni care îl modifică, instrucțiunile sunt executate secvențial, în ordinea în care apar în codul sursă.

6. Enumerați cele patru categorii de instrucțiuni din C++ și rolul fiecăreia.

Secvențiale (păstrează ordinea normală), de selecție (aleg o ramură de execuție, ex: if), de ciclare (repetă un bloc, ex: while) și de salt (transferă controlul sau întrerup execuția, ex: break, return).

7. Care este diferența dintre o instrucțiune și o structură de control?

Instrucțiunea este construcția concretă a limbajului de programare (ex: if, while). Structura de control este modelul conceptual după care este organizat fluxul execuției (secvențială, alternativă, repetitivă) — aceeași structură poate fi implementată prin instrucțiuni diferite.

8. Ce înseamnă „imbricarea" structurilor de control și de ce trebuie folosită cu grijă?

Imbricarea apare atunci când o structură de control este cuprinsă în corpul altei structuri de control (un if în alt if, sau o structură alternativă într-o structură repetitivă). Permite descrierea unor procese complexe, dar prea multe niveluri de imbricare fac programul greu de citit — de aceea se recomandă folosirea consecventă a acoladelor și a indentării.

9. Ce sunt schemele logice și pseudocodul, și de ce sunt utile?

Sunt forme intermediare de reprezentare a unui algoritm, între formularea unei probleme și implementarea ei în cod. Schema logică reprezintă vizual, prin simboluri standardizate, pașii și fluxul de execuție; pseudocodul îi descrie textual, fără reguli sintactice rigide. Ambele ajută la proiectarea unei soluții înainte de a scrie codul propriu-zis.

10. Ce rol joacă o condiție într-o instrucțiune if?

Condiția este o expresie care este evaluată înainte de a decide dacă instrucțiunea-corp va fi executată. Dacă expresia este adevărată, corpul este executat; dacă este falsă, corpul este omis, iar execuția continuă cu instrucțiunea următoare.

11. Care este diferența dintre o structură alternativă simplă și una dublă?

Structura alternativă simplă (if) execută o acțiune numai dacă o condiție este adevărată, fără nicio alternativă explicită dacă e falsă. Structura alternativă dublă (if–else) alege întotdeauna una dintre exact două ramuri, mutual exclusive.

12. Cum funcționează selecția multiplă printr-o cascadă else if? De ce contează ordinea condițiilor?

Condițiile sunt verificate în ordine, iar la prima condiție adevărată se execută ramura corespunzătoare, restul lanțului fiind ignorat. Dacă două condiții se pot suprapune (ex: nota >= 5 și nota >= 9), condiția mai restrictivă trebuie plasată prima — altfel ramura ei nu va fi niciodată atinsă.

13. Ce este o instrucțiune de selecție imbricată și ce precauție trebuie luată la scrierea ei?

Este o instrucțiune de selecție care apare în corpul altei instrucțiuni de selecție, permițând exprimarea unor decizii dependente unele de altele. Precauția principală: folosirea acoladelor, pentru a face explicită asocierea dintre fiecare if și eventualul lui else, evitând ambiguitatea „dangling else".

14. De ce nu este suficient să scrii doar o succesiune de instrucțiuni pentru orice program?

Pentru că multe probleme reale cer ca anumite acțiuni să fie executate doar în anumite condiții, să se aleagă între mai multe variante, sau să se repete de mai multe ori — comportamente pe care execuția strict secvențială nu le poate exprima. De aceea sunt necesare structurile de control (alternativă, repetitivă) pe lângă succesiunea simplă a instrucțiunilor.

15. La ce ajută secțiunea „Restricții și precizări" dintr-un enunț de problemă, chiar și pentru probleme simple?

Restricțiile precizează limitele valorilor de intrare (de exemplu, intervale numerice) și, adesea, semnalează cazuri speciale care trebuie tratate explicit — cum ar fi împărțirea la zero sau valori negative acolo unde intuitiv ai aștepta doar valori pozitive. Citirea restricțiilor înaintea proiectării algoritmului ajută la evitarea unor bug-uri care nu apar la testele simple, dar apar la valori extreme.

Rezumat – De reținut

Cele mai importante idei din această sesiune
  1. O instrucțiune este o construcție a limbajului care descrie o acțiune ce trebuie executată — spre deosebire de o expresie, care este evaluată și produce o valoare.
  2. O instrucțiune compusă (zero, una sau mai multe instrucțiuni între acolade) formează un bloc; în C++, cei doi termeni sunt echivalenți.
  3. Blocurile grupează instrucțiuni și delimitează un domeniu de vizibilitate pentru variabilele declarate în interior; ele pot fi imbricate.
  4. Instrucțiunile se împart în patru categorii: secvențiale, de selecție (if, if–else, switch), de ciclare (while, do–while, for) și de salt (break, continue, return, goto).
  5. Fluxul de execuție descrie ordinea instrucțiunilor executate; implicit este secvențial, dar poate fi ramificat (selecție), repetat (ciclare) sau transferat (salt).
  6. O structură de control (secvențială, alternativă, repetitivă) este modelul conceptual de organizare a fluxului; o instrucțiune este construcția concretă a limbajului prin care acel model este implementat — cele două niveluri nu trebuie confundate.
  7. Structurile de control pot fi combinate și imbricate pentru a descrie comportamente mai complexe — dar prea multe niveluri de imbricare reduc lizibilitatea.
  8. Schemele logice (reprezentare grafică) și pseudocodul (reprezentare textuală) sunt instrumente utile pentru proiectarea unui algoritm înainte de a-l scrie în cod.
  9. Structura alternativă simplă (if) execută condiționat o acțiune; structura alternativă dublă (if–else) alege între exact două ramuri mutual exclusive; selecția multiplă se face prin cascadă else if sau prin switch.
  10. Structurile de selecție pot fi imbricate; fără acolade, asocierea unui else cu if-ul corect poate deveni ambiguă — regula este că se asociază cu cel mai apropiat if fără else.
  11. Erori frecvente: ; rătăcit după condiția lui if, lipsa acoladelor la mai multe instrucțiuni-corp, ordinea greșită a condițiilor într-o cascadă else if, scrierea unei inegalități duble ca în matematică (1 < x < 5) în loc de x > 1 && x < 5.
  12. Orice problemă se poate formula ca un enunț de tip „platformă de exerciții": cerință, date de intrare, date de ieșire, restricții, un exemplu — și rezolvată în patru pași: date de intrare → date de ieșire → proiectarea algoritmului → scrierea codului.
  13. Instrucțiunile de ciclare, deși menționate aici pentru completarea clasificării, vor fi studiate în detaliu în sesiunea următoare.
